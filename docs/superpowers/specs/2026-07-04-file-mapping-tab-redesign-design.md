# Дизайн: пересбор вкладки «Просмотр в Finder» (сопоставление файл→язык)

Дата: 2026-07-04. Тема: замена нынешней вкладки сопоставлений на удобный инструмент
управления правилами «маска файла → подсветка», с починкой расхода памяти и добавлением
поддержки glob-масок.

## Зачем

Нынешняя вкладка (`App/FileTypesTab.swift` + `SettingsModel.previewRules`) неудобна и течёт
по памяти:

- **Расход памяти.** `previewRules` — вычисляемое свойство, которое на каждый пересчёт `body`
  заново строит массив из **всего** датасета linguist (тысячи расширений и имён), сортирует его,
  а `List` рисует строки, где в каждой сидит `Picker` на **все 218+ языков**. Тысячи строк ×
  сотни пунктов меню = приложение уходит в «ожидание ответа» уже при прокрутке.
- **Ничего не отражает.** Человек видит простыню чужих дефолтов, а не свои настройки. «На берегу»
  он вообще не знает, какие форматы с какой подсветкой сопоставлены.
- **Нет масок.** Разрешение (`PreviewResolution.resolvePreview`) умеет только точное имя файла
  (`byFilename[name]`) и расширение по последней точке (`byExtension[ext]`). `Dockerfile` ловится,
  а `Dockerfile.Dev`, `*.config.js`, `*.djhtml` — нет. Живой кейс пользователя (`*.djhtml` под
  сторонней грамматикой Django) сейчас не выразим.

## Чего хочет пользователь (два сценария)

1. **Назначить свою подсветку на свои файлы.** Поставил грамматику (напр. Django-шаблоны) и хочет
   красить ей `*.djhtml`. При этом заранее **не знает**, что у нас уже сопоставлено. Значит
   инструмент добавления обязан подсказывать (поиск по языкам с автодополнением) и предупреждать
   о конфликте с дефолтом.
2. **Поправить существующее.** Переназначить / выключить / удалить сопоставление, потому что в его
   контексте файл должен выглядеть иначе. Наизусть он не помнит, что куда назначено → вход через
   **поиск с подсказками**, а не через прокрутку горы.

## Область и границы

- **В области:** модель правил, glob-разрешение (fnmatch: `*` и `?`), переписанная вкладка,
  живая справка о дефолте и о перехвате, починка памяти, слоистые тесты.
- **Вне области:** сложные glob (классы `[...]`, регулярки); расширение набора перехвата Слоя A под
  новые `dyn.*`-расширения (проверим на живом `djhtml` при тестировании, список сейчас не трогаем);
  импорт `.vsix` и витрина «Темы» (не меняются).

## Решения (развилки, закрытые на brainstorm)

1. **Модель данных — единый упорядоченный список правил** (а не пять параллельных структур).
   Явный приоритет, единый источник для «покажи мои правки», память чинится сама.
2. **Маски — простой glob (fnmatch: `*`, `?`)** по полному имени файла. Частый случай `*.ext`
   распознаём как быстрый поиск по расширению. Без классов/регулярок.
3. **Вкладка по умолчанию показывает только правки пользователя.** Датасет — фоновые словари,
   виден только под активный поиск и с потолком по числу строк.
4. **Честный статус перехвата в листе добавления** (вариант B): пока человек печатает шаблон,
   показываем, сможем ли мы вообще перехватить такой файл. Чтобы правило не молчало втихую.

## Стена перехвата (важная оговорка)

Вкладка живёт на **Слое B** — «каким языком красить дошедший файл». Дойдёт ли файл, решает
**Слой A** — статические UTI в `Info.plist`, испечённые при сборке/подписи. Правило пользователя не
может на лету расширить этот список. Три исхода для расширения:

1. Система знает как текст/код, **или** мы объявили (выверенные системные UTI + экспортный
   `com.quicklookers.source-code` на 652 свободных расширения) → файл доходит → **правило работает**.
2. Система знает как настоящий не-код (`.mts`=видео, `.app`, `.dds`…) → мы намеренно не объявляем
   (объявить = сломать чужие настоящие файлы) → файл к нам не попадает → **правило молчит**.
3. Система не знает (`dyn.*`): если расширение в испечённом списке (652) → доходит; если совсем
   невиданное → остаётся `dyn.*`, к нам не попадает → **правило молчит**.

Потолок для `dyn.*` — испечённый список; wildcard-UTI не существует, «поймать все неизвестные»
нельзя. glob бьёт по этой стене чаще: `Dockerfile.*` — это `Dockerfile.dev` с расширением `.dev`,
которого система не знает и в списке нет. Поэтому лист добавления **честно показывает статус**, а
список перехвата в этой задаче не расширяется.

## Архитектура и компоненты

### SettingsKit (чистое, под `swift test`)

- **`PreviewRule`** — модель правила:
  ```
  struct PreviewRule: Codable, Equatable, Identifiable {
      var id: UUID
      var pattern: String            // glob по полному имени файла
      var action: RuleAction         // .assign(languageId) | .neutral
      var isEnabled: Bool
  }
  enum RuleAction: Codable, Equatable { case assign(languageId: String); case neutral }
  ```
- **`ManagerSettings` v3** — четыре структуры
  (`extensionOverrides`/`filenameOverrides`/`disabledExtensions`/`disabledFilenames`) **заменяются
  одним** `previewRules: [PreviewRule]`. Поля `disabledLanguageIds` (Слой 1), `activeThemeId`,
  `font` — без изменений. `currentSchemaVersion = 3`.
- **`GlobMatcher`** — компиляция шаблона в матчер по полному имени файла:
  - только литералы, без `*`/`?` → точное имя файла;
  - ровно `*.<segment>` без прочих спецсимволов → быстрый путь: сравнение по расширению;
  - иначе → fnmatch (`*` = любая последовательность, `?` = один символ).
  Плюс мера **специфичности** шаблона (число литеральных символов / отсутствие wildcard) для
  разрешения конфликтов.
- **`resolvePreview(fileName:pathExtension:associations:settings:)`** переписан:
  1. Правила пользователя, отсортированные по убыванию специфичности (точное имя > glob с бо́льшим
     числом литералов > голое расширение); первое **включённое** совпадение решает
     (`.assign` → highlight, `.neutral` → нейтраль).
  2. Иначе датасет: `byFilename[name]`, затем `byExtension[ext]`.
  3. Иначе нейтраль.
  Выключенный в Слое 1 язык по-прежнему форсит нейтраль (проверка `isLanguageEnabled`).
- **`searchDataset(query:limit:)`** — поиск по датасету для вкладки: совпадения по расширению,
  имени файла и имени языка, с потолком `limit`. **Фильтруем словари, потом строим строки** только
  для попаданий — никакого полного обхода/построения тысяч строк.

### Классификатор перехвата (в хосте)

- **`interceptionStatus(forExtension:)` → `.intercepted` / `.systemNonCode(typeName) / .unknownNotDeclared`.**
  Использует `UTType(filenameExtension:)` для вердикта системы и сверяется с нашим объявленным
  набором перехвата, прочитанным из бандла (`UTExportedTypeDeclarations` хоста + `QLSupportedContentTypes`
  расширения). Ядро классификации — чистая функция на поданных входах (объявленный набор + результат
  `UTType`), тестируемая без реального `Info.plist`. Точный способ чтения набора из бандла уточняется
  в плане.

### App (SwiftUI)

- **`FileTypesTab`** переписан:
  - поле поиска сверху;
  - список = «Мои правила» (из `settings.previewRules`); при активном поиске — ещё секция
    «По умолчанию» с капнутыми совпадениями датасета;
  - кнопка `+ Добавить правило`;
  - строка правила = текст + тумблер + контекстное меню (Изменить / Удалить). **Ни одного `Picker`
    в строках.**
- **`AddRuleSheet`** (новый) — лист добавления/правки:
  - поле шаблона;
  - живая строка «Сейчас так: …» — во что шаблон разрешается сейчас (дефолт или «нейтрально»);
  - живой статус перехвата (✅ перехватим / ⚠️ система считает это `<тип>`, не сработает);
  - тумблер «язык / не подсвечивать»;
  - **поиск-выбор языка по живому каталогу** (218 + импортированные), один инстанс в листе.
- **`SettingsModel`** — убрать тяжёлое `previewRules`; добавить:
  - `userRules` (проекция `settings.previewRules`);
  - `searchRules(query:limit:)` → `(mine:[…], defaults:[…])`, фильтр-потом-строки, капнутый;
  - CRUD: `addRule`, `updateRule`, `deleteRule`, `toggleRule(_:on:)`;
  - `materializeDefaultOverride(pattern:)` — «Изменить» у дефолта создаёт правило-перекрытие;
  - `currentResolution(forPattern:)` — для строки «Сейчас так»;
  - `interceptionStatus(forPattern:)` — для строки статуса перехвата.

## Поток данных

- **Показ файла** (расширение Preview): `PreviewViewController → resolvePreview(name, ext,
  associations, settings) → highlight(lang) | neutral`. Точка входа та же, логика внутри новая.
  Настройки читаются из App Group, как сейчас.
- **Вкладка** (хост): `SettingsModel.userRules ↔ settings.previewRules ↔ settings.json`
  (App Group, атомарная запись через `SettingsStore`). Правки — через `update{}` с ростом
  `settingsVersion`.

## Ошибки и краевые случаи

- Пустой/битый шаблон → «Сохранить» заблокирован.
- Дубль шаблона → правим существующее правило, не плодим второе.
- Правило на язык, выключенный в Слое 1 → информируем (показываем как выключенное), не молча роняем.
- **Миграции нет:** `settings.json` со `schemaVersion < 3` сбрасывается в `.default` (пользователей
  ещё нет), как и при переходе на v2.
- Действие `.neutral` = подавить дефолтную подсветку → нейтральный показ (`NeutralPage`).
- Нет контейнера App Group → окно работает, предупреждение, правки не сохраняются (как сейчас).

## Тестирование (слоями, по плейбуку)

- **Unit (SettingsKit):**
  - `GlobMatcher`: `*.djhtml`, `*.config.js`, `Dockerfile.*`, `?`-шаблон, точное имя; быстрый путь
    `*.ext`; мера специфичности.
  - `resolvePreview`: приоритет пользователь > датасет; специфичность среди правил пользователя;
    учёт `isEnabled`; `.neutral`; форс нейтрали при выключенном языке Слоя 1.
  - `PreviewRule` / `ManagerSettings` v3: Codable-roundtrip; дефолт; сброс при `schemaVersion < 3`.
  - `searchDataset`: совпадения по расширению/имени/языку; соблюдение потолка; отсутствие полного
    построения строк.
- **Unit (классификатор перехвата):** на поданных входах → intercepted / systemNonCode / unknown.
- **Живьём (этап тестирования):** живой кейс `*.djhtml` под сторонней грамматикой (проверка всей
  цепочки и статуса перехвата), прогон App-тестов ⌘U, визуальная проверка вкладки и памяти.

## Критерий готовности

- Вкладка по умолчанию показывает только правила пользователя; прокрутка и поиск не уводят
  приложение в «ожидание ответа»; тяжёлых `Picker` в строках нет.
- Поддержаны glob-маски (`*`, `?`) по полному имени файла; `*.config.js` и `Dockerfile.*`
  выражаются и матчатся; `*.djhtml` красится сторонней грамматикой Django.
- Лист добавления честно показывает текущий дефолт и статус перехвата.
- Слоистые тесты зелёные; `/simplify` пройден.
