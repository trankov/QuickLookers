# Оптимизация показа превью — дизайн

**Дата:** 2026-06-29
**Фаза:** оптимизация показа (после фазы 4 «полная библиотека + расширенный перехват»).
**Цель:** убрать видимый дефект (длинные строки уезжают за край) и срезать стоимость показа — без изменений в движке.

## Что входит (группа A + кэш HTML)

Четыре рычага из заметки `notes/2026-06-28-preview-thin-slice-spikes.md`:

1. **Перенос строк** — длинные строки (минифицированный JSON) переносятся, а не уезжают за край. Всегда включён.
2. **Обрезка первого экрана** — потолок N строк для огромных файлов, чтобы не вешать движок и не тянуть гигантский файл в память. Прокрутка в пределах N работает.
3. **Тёплый `WKWebView`** — переиспользуем один вебвью на жизнь процесса, чтобы убрать выбросы 1–2,6 с от холодного старта WebContent.
4. **Кэш готового HTML** — повторный показ того же файла минует чтение, движок и сборку страницы.

Не входит: настройка «перенос строк» (перенос — константа), отдельная «версия настроек» в ключе кэша (не нужна, см. ниже), нативный порт движка.

## Принцип разделения

Держим уже сложившееся в проекте разделение:

- **Чистая тестируемая логика — в `QuickLookersPreviewKit`** (`swift test`, инъекция временной папки, как у `SettingsStore`/`CatalogSource`): обрезка, ключ и хранилище кэша, сборка страницы.
- **Склейка с WebKit и контейнером App Group — в расширении** (`PreviewViewController`): тёплый вебвью, чтение файла, проводка кэша/обрезки. Проверяется логами (warm-спайк), а не юнит-тестами.

## Global Constraints

- Swift 6.3 / SwiftPM (tools 5.9), цель macOS 13+.
- TDD строго: падающий тест → запуск (падает) → реализация → запуск (зелёный) → коммит, по одному шагу.
- Движок не трогаем; вывод — готовая HTML-строка для статичного показа в `WKWebView` с выключенным JS.
- Кэш — ускорение, не источник истины: любая ошибка кэша трактуется как промах и не ломает показ.
- Потолок кэша на диске — **5 МБ**, вытеснение LRU.
- Потолок обрезки — **2000 строк** (константа). Порог «гигантского» файла для ограниченного чтения — **2 МБ** (константа).
- Коммиты по-русски (`feat(preview): …` / `test(...): …`), трейлер `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. Работа в отдельной ветке, не в `main` напрямую.

## Компонент 1 — Перенос строк и обрезка (PreviewKit)

### Перенос строк

В `previewPageHTML` к стилю `pre.shiki` добавляются правила переноса:

```css
pre.shiki {
    white-space: pre-wrap;
    overflow-wrap: anywhere;
    word-break: break-word;
}
```

`pre-wrap` сохраняет отступы кода и переносит длинные строки; `overflow-wrap: anywhere` / `word-break: break-word` ломают непрерывные строки без пробелов (минифицированный JSON). Настройки нет — всегда включено.

### Обрезка

Новая чистая функция в `Sources/QuickLookersPreviewKit/CodeTrim.swift`:

```swift
/// Режет код до первых `max` строк. truncated=true, если что-то отрезано.
public func trimToFirstLines(_ code: String, max: Int) -> (code: String, truncated: Bool)
```

- Делит по `\n`. Если строк ≤ `max` — возвращает исходный код, `truncated: false`.
- Если строк > `max` — берёт первые `max`, `truncated: true`.
- Пустой ввод — `("", false)`.

Хелпер ограниченного чтения (там же): расширение читает файл через него, чтобы не тянуть гигант в память.

```swift
/// Читает не более `maxBytes` префикса файла как UTF-8 (с запасом на хвостовой
/// многобайтовый символ — отбрасываем неполный последний символ). Для файлов
/// меньше порога вызывающий читает целиком обычным способом.
public func readBoundedPrefix(of url: URL, maxBytes: Int) throws -> String
```

### Плашка «обрезано»

`previewPageHTML` получает необязательный параметр и при обрезке дорисовывает внизу неинтерактивную плашку:

```swift
public func previewPageHTML(highlighted: String, truncatedNotice: String? = nil) -> String
```

`truncatedNotice == nil` — поведение как сейчас (обратная совместимость с текущими вызовами и тестами). Не `nil` — после фрагмента вставляется блок с текстом плашки (напр. «Показаны первые 2000 строк»). Текст формирует вызывающий — `previewPageHTML` его только вставляет.

### Тесты (PreviewKit)

- `CodeTrimTests`: ровно N строк (не обрезает), N+1 (обрезает до N, truncated), пусто, одна строка.
- `readBoundedPrefix`: файл меньше лимита читается целиком; файл больше лимита — префикс не длиннее лимита; не падает на многобайтовом символе на границе.
- `PreviewPageTests` (расширить): HTML содержит `pre-wrap`; при `truncatedNotice` плашка присутствует, при `nil` — отсутствует; фрагмент по-прежнему вставлен дословно.

## Компонент 2 — Тёплый WKWebView (расширение)

Сейчас `loadView` создаёт новый `WKWebView` на каждый показ → иногда холодный старт WebContent (выбросы 1,3–2,6 с). Лечим переиспользованием.

- **Статический общий `WKWebView`** на жизнь процесса, рядом с уже тёплыми `cachedEngine` / `cachedThemeIds`. Конфиг тот же: `allowsContentJavaScript = false`.
- В `loadView`: `self.view = Self.sharedWebView` вместо создания нового. При вставке в новую иерархию вид переезжает к текущему контроллеру.
- `navigationDelegate` переназначается на текущий контроллер в начале каждого показа (статический вебвью переживает контроллеры, делегат должен указывать на живой).
- Континуация `didFinish` — без изменений; ждём загрузку перед возвратом.

**Риск и границы.** Вид может быть в одной иерархии за раз. QuickLook показывает один файл за раз, прошлый контроллер к моменту нового показа освобождён — конфликта нет. Если всплывёт (два одновременных превью) — видно по логу.

**Проверка:** лог-спайк (`warm=true`, отсутствие выбросов на повторных показах), не юнит-тест.

## Компонент 3 — Кэш HTML (PreviewKit + контейнер App Group)

Цель: повторный показ того же файла минует чтение, движок и сборку страницы.

### Ключ кэша

Собирается дёшево, **без чтения содержимого файла**:

- путь файла + время правки (`mtime`) + размер;
- `languageId` + разрешённый `themeId` (вбирает тему и светлый/тёмный режим);
- потолок обрезки N;
- **версия ресурсов бандла** (`bundleVersion`) — при обновлении приложения грамматики/темы/движок меняются, и старый HTML неактуален.

Из этих полей берётся короткий стабильный хэш — это имя файла записи в кэше.

Почему нет отдельной «версии настроек»: перенос строк теперь константа, а единственная настройка, влияющая на вывод, — тема, и она уже в ключе через `themeId`. Ключ самодостаточен.

`bundleVersion` даёт расширение (читает версию своего бандла) и передаёт в кэш — сам кэш про бандлы не знает.

```swift
public struct HTMLCacheKey: Equatable {
    public init(path: String, mtime: TimeInterval, size: Int,
                languageId: String, themeId: String, maxLines: Int, bundleVersion: String)
    /// Короткий стабильный хэш всех полей — имя файла в кэше.
    public var fileName: String { get }
}
```

### Хранилище

Новая тестируемая единица `Sources/QuickLookersPreviewKit/HTMLCache.swift`, которой инъецируется папка кэша (как временная папка в тестах `SettingsStore`):

```swift
public struct HTMLCache {
    public init(directory: URL, maxBytes: Int)              // maxBytes = 5 * 1024 * 1024
    public func lookup(_ key: HTMLCacheKey) -> String?      // читает HTML, обновляет отметку использования
    public func store(_ key: HTMLCacheKey, html: String)    // атомарная запись
    public func evictIfNeeded()                             // LRU до укладывания в maxBytes
}
```

- `lookup`: если файла нет / не читается — `nil` (промах). При попадании обновляет отметку «использован» — трогает `mtime` файла кэша (`setAttributes`), чтобы LRU видел свежесть. Возвращает HTML.
- `store`: пишет HTML атомарно (temp + переименование). Ошибка записи — проглатывается (показ уже идёт).
- `evictIfNeeded`: суммирует размеры файлов кэша; если больше `maxBytes` — удаляет по возрастанию `mtime` (давно не использованные первыми), пока не уложится. Отметка использования — `mtime` файла кэша, отдельного индекса нет.

### Папка кэша

Подкаталог в контейнере App Group: `quickLookersContainerURL()?.appendingPathComponent("Caches/html")`. Путь готовит расширение и передаёт в `HTMLCache`; сам кэш про App Group не знает. Если контейнера нет — расширение работает без кэша (каждый показ считает заново), показ не ломается.

### Конвейер показа (расширение)

1. собрать дешёвый ключ (без чтения файла — `mtime`/`size` из атрибутов);
2. `lookup` — попадание → берём HTML, пропускаем чтение + движок + сборку;
3. промах → читаем файл (целиком или ограниченным префиксом при размере > 2 МБ), обрезаем до N, красим, собираем страницу, `store`;
4. грузим HTML в тёплый вебвью, ждём `didFinish`;
5. `evictIfNeeded` — **после** возврата (асинхронно, в `try?`), чтобы не висело на горячем пути.

### Тесты (PreviewKit)

- `HTMLCacheKey`: `fileName` стабилен при тех же входах; меняется при смене любого поля (`mtime`, `themeId`, `bundleVersion`, `maxLines`, `path`, `size`, `languageId`).
- `HTMLCache`: `store` → `lookup` возвращает тот же HTML; `lookup` на пустой папке — `nil`; битый/обрезанный файл — `nil` (промах, не падение); `evictIfNeeded` при превышении потолка удаляет именно давно не использованные (по `mtime`), свежие остаются.

## Поток данных (итог)

```
preparePreviewOfFile(url)
  → атрибуты файла (mtime, size)  [без чтения содержимого]
  → previewLanguageId / resolvedThemeId  [как сейчас]
  → HTMLCacheKey(path, mtime, size, lang, theme, N, bundleVersion)
  → cache.lookup(key)
       ├─ HIT  → html
       └─ MISS → read (целиком | префикс при >2 МБ)
                 → trimToFirstLines(code, N)
                 → engine.highlightToHTML
                 → previewPageHTML(highlighted, truncatedNotice?)
                 → cache.store(key, html)
  → sharedWebView.loadHTMLString(html); await didFinish
  → (async) cache.evictIfNeeded()
  → log(pid, warm, lang, theme, ms)
```

## Обработка ошибок

- Любая ошибка кэша (чтение/запись/вытеснение) → промах или проглатывание, показ идёт обычным путём.
- Нет контейнера App Group → работаем без кэша.
- Чтение файла падает (нет доступа/не UTF-8) → как сейчас: бросаем, QuickLook откатывается к системному показу.
- Тёплый вебвью: при невозможности переиспользовать — видно по логу; откат на «вебвью под контроллер».
