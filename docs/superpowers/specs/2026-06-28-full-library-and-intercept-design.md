# Полная библиотека языков/тем + расширенный перехват — дизайн-документ

**Дата:** 2026-06-28
**Статус:** черновик на ревью
**Платформа:** macOS 13+ (целевая проверка — macOS 26 Tahoe)

## Зачем

Сейчас подключено по минимуму (под тонкий срез фазы 2): 3 грамматики (swift,
javascript, json), 2 темы (dark-plus, light-plus), 3 перехватываемых типа.
Этого мало, чтобы трогать оптимизацию показа на разном материале. Цель фазы —
**подключить всю библиотеку Shiki (≈200 языков, ≈60 тем)** и **расширить
перехват в Finder**, чтобы пробел срабатывал на широком наборе файлов кода.
Тогда последующую оптимизацию (тёплый WebView, перенос строк, обрезка первого
экрана, кэш HTML) можно проверять на реальном разнообразии, а не на трёх файлах.

Это одна фаза из двух частей: **Слой 1** (библиотека подсветки) и **Слой 2**
(перехват в Finder). Слой 2 зависит от Слоя 1.

## Дисциплина источников

Документ строит решения **только на проверенном**. Всё, что не подтверждено
документацией или нашим рабочим кодом, помечено как **спайк** и не считается
фактом. Конкретные строки UTI и имена API, которые не проверены, в документе
**не выдумываются** — вместо них стоит способ их добыть.

### Что проверено (с источниками)

- **П1.** Превью своих типов объявляются массивом `QLSupportedContentTypes` в
  `Info.plist` расширения.
  [Providing Quick Look previews](https://developer.apple.com/documentation/QuickLook#Providing-Quick-Look-previews-for-your-data-types)
- **П2.** View-controller-расширение = `QLPreviewingController` +
  `preparePreviewOfFile(at:completionHandler:)` (уже используется в проекте).
  [Quick Look](https://developer.apple.com/documentation/QuickLook#Preview-extensions)
- **П3.** Apple советует делать preview-расширение **только для своих
  форматов**; стандартные (текст, изображения, PDF, аудио/видео, USDZ и др.)
  система превьюит сама.
  [Convenience: Generate previews for custom data formats](https://developer.apple.com/documentation/TechnologyOverviews/convenience#Generate-previews-for-custom-data-formats)
- **П4.** Для **Thumbnail**-расширения: перечислять **точные UTI**;
  родительский UTI, которому тип соответствует, — **недостаточно**.
  [Providing Thumbnails — Update the Extension's Info.plist](https://developer.apple.com/documentation/QuickLookThumbnailing/providing-thumbnails-of-your-custom-file-types#Update-the-Extensions-Infoplist)
- **П5.** Системный превьюер показывает распространённые типы (текст по
  `public.text`, CSV, PDF, картинки…); набор **меняется от версии к версии**.
  [QLPreviewController](https://developer.apple.com/documentation/QuickLook/QLPreviewController)
- **П6.** Свой UTI объявляется через `UTExportedTypeDeclarations`
  (`UTTypeIdentifier`, `UTTypeConformsTo`, `UTTypeTagSpecification` →
  `public.filename-extension`).
  [Building a document-based app with SwiftUI](https://developer.apple.com/documentation/SwiftUI/Building-a-document-based-app-with-SwiftUI#Export-a-custom-document-type)
- **П7 (наша эмпирика).** Точные UTI для Preview **работают**: наши
  `public.swift-source` / `public.json` / `com.netscape.javascript-source`
  показываются end-to-end (фаза 2, подтверждено).

### Что НЕ проверено — спайк, не факт

- **С1.** Применимо ли правило «точный UTI, не родитель» (П4) к **Preview**.
  Подтверждено только для Thumbnail.
- **С2.** Кто побеждает, когда мы объявляем точный UTI типа, который превьюит
  и система (precedence / «зарезервированные» типы). В доках нет.
- **С3.** Конкретные системные UTI-строки для каждого языка. Не выдумываем —
  добываем из системы (см. ниже).
- **С4.** Есть ли у Shiki перечисление языков и их расширений через API, и в
  каком поле человекочитаемое имя. Подтвердить через Context7 на реализации.

## Слой 1 — библиотека подсветки

**Цель:** все языки и темы Shiki в бандле пакета и в каталоге/настройках.

**Что уже держится (проверено по коду):**
- `FileCatalogSource` читает **все** `*.json` из `Resources/grammars/` и
  `Resources/themes/` и строит каталог. Добавление файлов наполняет Слой 1
  **без правок Swift**.
- Движок грузит грамматику **лениво** по языку (`qlRegisterLang` /
  `qlHighlight` в `js/src/highlight.mjs`): в память попадает только то, что
  реально показывали.

**Что делаем:**
1. **Обобщить `js/extract-resources.mjs`.** Сейчас списки `GRAMMARS`/`THEMES`
   захардкожены тремя/двумя. Заменить на перечисление полного набора из
   `@shikijs/langs` и `@shikijs/themes`. Точный способ перечисления и поле
   человекочитаемого имени — **уточнить через Context7 по Shiki** (С4), в
   документе не фиксируем имя API во избежание выдумки.
2. **Человекочитаемые имена в каталоге.** У грамматик Shiki поля `displayName`
   нет — сейчас в каталоге окажутся технические id (`javascript`). Имя берём из
   метаданных Shiki в момент extract и кладём в дескриптор как `displayName`
   (поле, читаемое `FileCatalogSource`). Источник имени — по С4.
3. **Вложенные грамматики.** Язык может ссылаться на другие (встраиваемые)
   грамматики; без них движок не соберёт подсветчик. Extract-скрипт должен
   класть и зависимости. Конкретная механика (как Shiki отдаёт зависимости) —
   **research-задача в плане**, без догадок в этом документе.
4. **Темы.** Аналогично грамматикам: извлечь все, признак тёмная/светлая —
   из поля `type` (уже читается `FileCatalogSource`).
5. **Размер и старт.** Полный набор грамматик заметно больше трёх. Влияние на
   холодный старт — **замерить** (бенчмарк уже есть в проекте). Если старт
   распухнет, рычаг — не грузить всё разом (ленивость уже на месте); вывод по
   замеру, не заранее.

**Граница ответственности:** Слой 1 не трогает Info.plist и перехват — только
ресурсы, extract-скрипт и (если потребуется по С4) дескрипторы каталога.

## Слой 2 — перехват в Finder

**Принцип охвата (на проверенном):**
- В `QLSupportedContentTypes` объявляем **точные UTI** наших языков — точные
  UTI для Preview работают (П7). На зонтик-родитель **не закладываемся**:
  для Thumbnail он не работает (П4), для Preview не проверено (С1).
- **«Отдать ОС» = не объявлять UTI.** Единственная опора, держащаяся на доках:
  расширение вызывается только для объявленных типов, стандартные система
  превьюит сама (П3, П7). Рантайм-«верни системе» не обещаем — поведение не
  проверено (Спайк C).

**Откуда берём строки UTI (С3 — добываем, не выдумываем):**
1. Берём список наших языков и их расширения файлов.
2. Для каждого расширения **резолвим системный UTI программно** через
   `UTType(filenameExtension:)` (документированный API UniformTypeIdentifiers).
   Строки UTI добывает машина из системы, а не автор документа.
3. Где системного UTI нет — объявляем **свой экспортируемый UTI** по расширению
   через `UTExportedTypeDeclarations` (П6).
4. Итог — таблица для `DeclaredTypes.all` (UTI → расширение → язык; структура
   уже есть) и набор UTI для `QLSupportedContentTypes` в `project.yml`.

**Набор языков для перехвата (Слой 2):** за основу — opt-out код-набор из
исходного дизайна (`2026-06-27-quicklookers-design.md`): Python, JS/TS/JSX/TSX,
C/C++, Java, Go, Rust, Swift, C#, PHP, Ruby, Kotlin, Dart, Scala, R, Perl, Vue,
YAML, TOML, JSON, Dockerfile, SQL, GraphQL, Jinja. Точный итоговый список
уточняется добычей UTI (шаг выше): язык войдёт в перехват, если для него есть
системный UTI или мы объявили свой.

**opt-out:**
- **Объявленный набор фиксируется на сборке** (П1): добавить/убрать тип =
  перегенерация `project.yml` + пересборка. Это основной «рубильник охвата».
- Рантайм-opt-out по языку (`previewDisabledLanguageIds`, уже в модели)
  оставляем, но **что он реально даёт** — пустой экран или возврат к системе —
  **не утверждаем** до Спайка C.

## Спайки (до того, как полагаться)

- **Спайк A (С1):** declared parent UTI для Preview — перехватывает или нет.
  Дизайн от ответа не зависит (берём точные UTI и так), спайк закрывает вопрос.
- **Спайк B (С2):** для типа, который превьюит и система (например `public.json`
  — у нас уже работает; и спорный вроде CSV), замерить на macOS 26, кто
  побеждает при объявленном точном UTI.
- **Спайк C:** когда контроллер **отказывается** по объявленному типу — macOS
  показывает родное превью или пустоту. Решает, возможен ли рантайм-«отдать ОС».

Спайки идут **в начале плана**: их исход уточняет финальный набор Слоя 2, но не
блокирует Слой 1.

## Тестирование (end-to-end)

- **Слой 1:** в приложении/расширении показать файлы разных языков из полного
  набора; сравнить картинку с VS Code на тех же темах; переключение тем из
  полного набора.
- **Слой 2:** пробел в Finder на файлах расширенного набора — перехват
  срабатывает, язык определяется по расширению, подсветка совпадает с VS Code.
- **Под оптимизацию:** большой и длинный (минифицированный) файл — материал для
  последующих замеров, ради чего фаза и затевалась.
- **Бенчмарк старта** до и после подключения полного набора грамматик.

## Что НЕ входит

- Сама оптимизация показа (тёплый WebView, перенос строк, обрезка, кэш HTML) —
  **следующая фаза**, эта лишь готовит для неё материал.
- Импорт тем/грамматик из VS Code/Cursor и `.vsix` — отдельная фаза.
- Системные типы opt-in (HTML/CSV/plist как осознанный выбор пользователя с
  предупреждением) — после спайков, отдельным решением; здесь только код-набор.
- Расширение Thumbnail — отложено (см. исходный дизайн-документ).
