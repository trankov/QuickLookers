# Вкладка «Форматы» + обратная связь импорта — дизайн

**Дата:** 2026-06-30

## Зачем

Живая проверка импорта `.vsix` вскрыла UX-проблемы:
- Список языков длинный (218), кнопка «Импортировать…» — в самом низу `Form`, новый пользователь её не находит; внутренней прокрутки нет, фильтра нет.
- Поле-сводка «Импортировано N, пропущено M» из общего `ImportModel.summary` показывается **в обеих вкладках** (импорт тем светится и под грамматиками), **зависает после удаления** (его никто не сбрасывает), а «пропущено M» (служебные грамматики-инъекции) пользователю непонятно.

## Область

- **Вкладка «Форматы» (грамматики)** — переработка (этот спек).
- **Обратная связь импорта** — переработка для обеих вкладок (этот спек).
- **Вкладка «Темы» (визуально)** — **отложено** до фичи «импорт из редактора»: двойное появление импортированной темы в списке и общая визуальная переработка темовой вкладки — не здесь. Здесь темовая вкладка получает только новую обратную связь импорта (как «Форматы»), список тем не трогаем.

## Дизайн

### Вкладка «Форматы» — три зоны (VStack)

```
Поиск языка: [____________]      ← TextField сверху, фильтр по мере ввода
┌──────────────────────────┐
│ ◉ Swift                  │     ← List в своём фрейме, прокрутка ВНУТРИ.
│ ◉ Zig            [–]      │       Контрол — Toggle (свитч), как сейчас.
│ ◯ JSON                   │       У импортированного — кнопка-минус (как сейчас).
│ … (фильтруется)          │
└──────────────────────────┘
─────────────────────────────    ← Divider
[ Импортировать… ]   ⚠ текст     ← кнопка всегда внизу; строка ошибки рядом (только при ошибке)
```

- **Поиск:** `TextField`, фильтрует `model.catalog.languages` без учёта регистра по `displayName` И `id`. Пустой запрос — весь список.
- **Список:** `List` с гибкой высотой (занимает место между поиском и нижней панелью), прокрутка внутри окна. Строка языка — **`Toggle` (переключатель-свитч, как сейчас)** + у импортированного (`model.importedIds.contains(id)`) кнопка-минус (удаление, как сейчас).
- **Низ:** кнопка «Импортировать…» закреплена под `Divider`, всегда видна. Рядом — строка ошибки (см. ниже).

### Обратная связь импорта (обе вкладки)

- **Постоянная сводка убрана.** Успех виден по списку: импортированное появляется (с минусом), удалённое исчезает. **Алерта нет.**
- **Ошибка — строка-подсказка у кнопки, только при ошибке/пустом результате.** Маленький красноватый текст рядом с «Импортировать…». При успехе текста нет. Строка **сбрасывается** при следующем успешном импорте или удалении (не залипает).
- При успехе **число пропусков не показываем** (служебные инъекции — шум).

### Контракт `ImportModel`

`summary` (постоянная сводка) убирается. Новый возврат импорта:

```swift
struct ImportOutcome {
    let didChange: Bool     // импортировано >0 → перечитать каталог, очистить строку ошибки
    let errorText: String?  // nil при успехе; текст при ошибке или «ничего не нашлось»
}
func runImport() -> ImportOutcome?   // nil = пользователь отменил пикер
```

Логика:
- импортировано N>0 → `ImportOutcome(didChange: true, errorText: nil)`;
- N==0 (contributes были, но всё отсеяно) → `ImportOutcome(didChange: false, errorText: "В файле не нашлось тем или грамматик для импорта.")`;
- ошибка `ImportError` → `errorText` = человеческая формулировка (нынешний `message(for:)`); прочее → «Не удалось прочитать файл.».

`remove(kind:id:)` — без изменений (ничего не сообщает; вызывающая вкладка после него очищает строку ошибки и перечитывает каталог).

### Поведение вкладки (FormatsTab и ThemesTab)

```swift
@State private var query = ""        // только FormatsTab
@State private var errorText: String?

// кнопка импорта:
if let outcome = importModel.runImport() {
    if outcome.didChange { model.reloadCatalog(); errorText = nil }
    else { errorText = outcome.errorText }
}
// кнопка-минус (удаление):
importModel.remove(kind:, id:); model.reloadCatalog(); errorText = nil
```

`ThemesTab` получает ту же обратную связь (строка ошибки + сброс), но список тем и его двойное появление **не трогаем** (отложено).

## Тестирование

UI-таргет, под `swift test` не покрывается. Проверка:
- `xcodebuild ... BUILD SUCCEEDED`;
- живая проверка пользователем: длинный список грамматик прокручивается внутри фрейма; поиск фильтрует; «Импортировать…» всегда внизу; импорт грамматики из `test-vsix/grammar-zig.vsix` → язык появляется с минусом; удаление → исчезает; битый файл → строка ошибки у кнопки, при успехе строки нет.

## Глобальные ограничения

- Контрол языка — **`Toggle` (свитч)**, не чекбокс.
- Артефакты XcodeGen не править руками; только `project.yml` при необходимости (вряд ли понадобится — правки в `App/*.swift`).
- Ветка отдельная, не `main`. Коммиты по-русски с трейлером `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- Двойное появление темы и визуальная переработка темовой вкладки — **вне области**, отложено.
