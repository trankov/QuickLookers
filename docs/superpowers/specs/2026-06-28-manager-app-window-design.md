# QuickLookers — окно приложения-менеджера, три вкладки (фаза 3)

**Дата:** 2026-06-28
**Статус:** реализован (фаза 3)
**Платформа:** macOS 13+, Xcode 26, Swift 6.3
**Предшествует:** общий дизайн — `2026-06-27-quicklookers-design.md`; движок реализован (фаза 1); расширение Preview работает сквозным срезом (фаза 2 — `2026-06-28-preview-extension-thin-slice-design.md`).

## Цель

Дать главному приложению-менеджеру первое настоящее окно — **три вкладки: «Форматы подсветки», «Темы», «Сопоставление с типами файлов»** — и завести **App Group-контейнер** как общий источник правды. Срез **сквозной, как в фазе 2**: выбор пользователя в окне сразу меняет показ по пробелу в Finder.

Это первый срез менеджера, не вся подсистема настроек. Намеренно отложено: импорт (`.vsix`, чтение конфига VS Code/Cursor), полный каталог Shiki, живой предпросмотр темы, кэш HTML, прочие настройки из общего дизайна.

## Решения по объёму (зафиксировано в брейншторме)

- **Сквозной срез.** Окно пишет настройки → расширение их читает и применяет. Доказываем всю цепочку «менеджер пишет — расширение читает» по-настоящему.
- **App Group заходит сразу** как фундамент. Это та «более тяжёлая подпись», что была отложена в фазе 2; берём её здесь.
- **Импорт отложен целиком.** Окно управляет тем, что уже вшито (3 языка, 2 темы). Кнопок «Импортировать…» в этом срезе нет, но модель и каталог спроектированы под будущий импорт.
- **Хранилище — файл `settings.json` в контейнере** (а не общий `UserDefaults`-suite). Причина: контейнер — единый источник правды, где уже будут лежать темы, грамматики и кэш HTML файлами; настройки тем же способом — единая модальность, и «версия настроек» для будущего ключа кэша ложится естественно.

## Готовность к будущему расширению через `.vsix`

Импортёра в срезе нет, но швы под него закладываем сразу:

1. **Каталог выводится из «библиотеки-источника», а не зашит списком.** Моделируем как «прочитать источник и перечислить, что в нём есть». В срезе источник — вшитые ресурсы пакета; позже тот же код смотрит в библиотеку внутри контейнера, которую наполняет импортёр. Импорт `.vsix` тогда = «положить ещё JSON-файлы», без правок модели.
2. **Метаданные читаем из самих файлов-дескрипторов.** Имя языка — из поля `name` грамматики; светлая/тёмная тема — из поля `type` темы; id — имя файла (как уже принято в движке: `имя файла = id = name`). Тот же путь чтения позже использует импортёр.
3. **Настройки ссылаются на языки/темы строковыми id и устойчивы к рассинхрону** (см. раздел «Ошибки и устойчивость»).
4. **Два слоя ведут себя по-разному** (ключевое):
   - **«Форматы подсветки» (Слой 1) — открытое множество.** Импорт свободно его расширяет: новый язык можно красить.
   - **«Сопоставление с типами файлов» (Слой 2) — ограничено статическим `Info.plist`.** Просмотр в Finder возможен только для UTI, заранее объявленных в `QLSupportedContentTypes` на этапе сборки. Импортированный язык можно **красить**, но **показывать новый тип в Finder** нельзя, пока его UTI не объявлен. Язык, чей тип не объявлен, во вкладку 3 не попадает.

## Терминология (для пользователя)

В надписях интерфейса используем слово «**просмотр**», а не «перехват»: пользователь думает «вижу ли я этот файл по пробелу», а не про механизм QuickLook-провайдера. «Перехват» остаётся только внутренним словом в коде. Принцип: идём от пользователя, а не от кода.

## Архитектура и границы модулей

Та же схема, что уже работает в проекте: логика — в тестируемом SwiftPM-пакете, Xcode-обвязка тонкая поверх.

```
Package.swift                          # + новый продукт/таргет QuickLookersSettingsKit
Sources/QuickLookersSettingsKit/       # НОВОЕ — чистая логика настроек (под swift test)
Sources/QuickLookersPreviewKit/        # остаётся обёртка HTML-страницы; LanguageMap уезжает
Tests/QuickLookersSettingsKitTests/    # НОВОЕ — XCTest, TDD

App/                                   # окно с тремя вкладками (заменяет заглушку)
PreviewExtension/                      # читает настройки через SettingsKit
project.yml                            # + entitlement App Group обоим таргетам
```

- **`QuickLookersSettingsKit`** (чистый Swift, под `swift test`) отвечает за: модель настроек, модель каталога, источник каталога, чтение-запись `settings.json` в контейнере, логику разрешения (активная тема; показывать ли данный файл и каким языком). Не зависит ни от движка, ни от UI.
- **Приложение** (SwiftUI, три вкладки) — тонкая оболочка: связывается с моделью настроек, пишет `settings.json`. Заменяет нынешнюю заглушку-окно.
- **Расширение** на каждом показе читает настройки через `SettingsKit`, по ним выбирает язык и тему. Нынешнюю статическую таблицу `PreviewKit.languageId(forPathExtension:)` **переносим в `SettingsKit`** (теперь она управляется данными) — чтобы не было двух источников правды. `PreviewKit` остаётся отвечать только за обёртку HTML-страницы.
- **App Group-контейнер** — общий каталог, доступный обоим таргетам. Сейчас в нём только `settings.json`; позже там же — темы, грамматики, кэш HTML.

Принцип: **менеджер пишет — расширение читает**, всё через файлы в контейнере.

## Модель настроек и каталог

Две разные вещи, их не смешиваем.

**Настройки** (сохраняются в `settings.json`) — выбор пользователя:
- `schemaVersion: Int` — версия формата файла (для совместимости).
- `settingsVersion: Int` — счётчик, растёт на каждое сохранение. Позже станет частью ключа кэша HTML.
- `disabledLanguageIds: Set<String>` — языки, которые пользователь **выключил** (вкладка «Форматы»). Модель opt-out: пусто = все языки каталога включены. Так новый язык из будущего импорта по умолчанию включён (его нет в множестве выключенных), и это поведение проверяемо уже сейчас.
- `theme: ThemeSelection` — `followSystem: Bool` + `lightThemeId: String` + `darkThemeId: String` + `fixedThemeId: String` (используется, когда `followSystem == false`).
- `previewDisabledLanguageIds: Set<String>` — языки, убранные из **просмотра** в Finder (вкладка «Сопоставление»). Тоже opt-out: пусто = все объявленные типы показываются. *(Имя внутреннее; пользователю — «просмотр».)*

**Каталог** (НЕ сохраняется, выводится из доступного):
- `languages: [LanguageInfo]` — `id`, `displayName`. Заполняется чтением метаданных из вшитых грамматик. Сейчас 3 (Swift, JSON, JavaScript). Размер не фиксирован.
- `themes: [ThemeInfo]` — `id`, `displayName`, `isDark: Bool` (из поля `type` темы). Сейчас 2 (`light-plus`, `dark-plus`).

**Таблица объявленных типов** (статическая в срезе, отражает `QLSupportedContentTypes`) — граница Слоя 2:
- записи `(uti, pathExtension, languageId)`: `(public.swift-source, swift, swift)`, `(public.json, json, json)`, `(com.netscape.javascript-source, js, javascript)`.

**Умолчания** (когда `settings.json` ещё нет): оба множества выключенных пусты (все языки включены и показываются); темы `light-plus`/`dark-plus`; «следовать за системой» включено. Это ровно нынешнее поведение расширения.

## Хранилище: `settings.json` в контейнере

- **Путь:** `<App Group-контейнер>/settings.json`. Контейнер — через `FileManager.containerURL(forSecurityApplicationGroupIdentifier: "group.com.quicklookers")`.
- **Запись (приложение):** атомарно — во временный файл и переименование, чтобы расширение не прочитало полузаписанный файл. На каждое сохранение `settingsVersion += 1`.
- **Чтение (расширение):** на каждом показе читаем заново (файл маленький, дёшево). Нет файла или битый → встроенные умолчания. Свежая установка без запуска приложения работает.
- **Без слежки за файлом:** ни file-watcher, ни KVO. Приложение пишет — расширение перечитывает при следующем показе.
- **Версия схемы:** при чтении неизвестная `schemaVersion` → откат на умолчания, не падаем.

## Окно: три вкладки

Окно заменяет нынешнюю заглушку. Одно окно с тремя вкладками (стандартный для macOS вид с переключателем вкладок сверху).

**Вкладка 1 — «Форматы подсветки» (библиотека).**
- Список языков из каталога, у каждого переключатель «включён». Сейчас 3 строки.
- Слой 1 — открытое множество, растёт с будущим импортом. Кнопка «Импортировать…» — позже, не в срезе.

**Вкладка 2 — «Темы».**
- Переключатель «Следовать за системой».
- Включено → два списка: светлая тема и тёмная тема (светлые/тёмные различаем по `isDark`).
- Выключено → один список: активная тема.
- Списки — из каталога тем. Импорт тем — позже (симметрично языкам), не в срезе. Живого предпросмотра темы в срезе нет.

**Вкладка 3 — «Сопоставление с типами файлов».**
- Перехват — на уровне **языка** (не отдельного расширения): по тумблеру на язык. Тумблер читается как «показывать просмотр для файлов этого языка в Finder».
- Рядом со строкой показаны расширения, которые покрывает язык (пояснение). Сейчас: Swift → `.swift`, JSON → `.json`, JavaScript → `.js`.
- Слой 2 — список строится из таблицы объявленных типов; язык, чей тип не объявлен, сюда не попадает.

**Связь вкладок 1 и 3.** Язык, выключенный на вкладке 1, нельзя показывать на вкладке 3 — нечего красить. Строки вкладки 3 для выключенных языков неактивны. В логике: фактический просмотр = `язык в просмотре` И `язык включён`.

## Сквозной поток данных

1. Пользователь щёлкает в окне → `SettingsKit` меняет модель → атомарно пишет `settings.json`, `settingsVersion` растёт.
2. Пробел на файле в Finder → расширение, `preparePreviewOfFile`.
3. Расширение читает настройки (или умолчания). По расширению файла находит язык через таблицу объявленных типов. **Нет языка / язык выключен / язык не в просмотре** → бросает ошибку → системный показ.
4. Иначе разрешает тему: смотрит оформление системы (`effectiveAppearance` вью расширения) → id темы (светлая/тёмная либо фиксированная).
5. Движок: `код + язык + тема → HTML` → `WKWebView` (как в фазе 2). Разница только в том, что язык и тема приходят из настроек, а не зашиты.

## App Group и подпись

- **Идентификатор группы:** `group.com.quicklookers`.
- В `project.yml` обоим таргетам (приложение + расширение) добавляем entitlement `com.apple.security.application-groups: [group.com.quicklookers]`, перегенерируем проект. Существующие entitlements сохраняем (песочница, `network.client`, `files.user-selected.read-only`).
- Контейнер — через `containerURL(forSecurityApplicationGroupIdentifier:)`, одинаковый id с обеих сторон.
- Это «более тяжёлая подпись», отложенная в фазе 2. Личный Team в автоматическом режиме App Group поддерживает; отдельный provisioning-портал не нужен.
- **Ручная проверка на машине пользователя** (как регистрация в фазе 2): запустить хост из Xcode, убедиться, что контейнер доступен и `settings.json` пишется/читается обеими сторонами.

## Ошибки и устойчивость

- **Нет `settings.json` или битый** → встроенные умолчания; расширение красит как прежде, ничего не висит.
- **Неизвестная `schemaVersion`** → умолчания, не падаем.
- **В настройках id, которого нет в каталоге** (тему/язык удалили) → тема откатывается на встроенную по умолчанию; неизвестный язык игнорируется.
- **В каталоге язык, которого нет в настройках** (появился через импорт) → считаем включённым.
- **Ошибка записи `settings.json`** в приложении → не падаем, держим состояние в памяти, показываем ненавязчивое сообщение.
- **Контейнер App Group недоступен** (подпись/entitlement не настроены) → приложение сообщает; расширение работает на умолчаниях. Явный маркер кривой подписи, не молчаливая поломка.
- **Ограничение статического plist:** включить просмотр для типа, не объявленного в `QLSupportedContentTypes`, на лету нельзя. В срезе все три типа объявлены.

## Проверка работоспособности (как тестировать)

**`swift test` для `QuickLookersSettingsKit` (по TDD):**
- кодирование/декодирование настроек туда-обратно;
- `settingsVersion` растёт на каждое сохранение;
- умолчания при отсутствующем/битом файле;
- разрешение темы: «следовать за системой» вкл (тёмная/светлая), выкл (фиксированная), пропавший id → дефолт;
- разрешение просмотра: нет языка для расширения → ничего; язык выключен → ничего; язык не в просмотре → ничего; счастливый путь → язык;
- устойчивость: незнакомый id в настройках игнорируется; новый язык каталога включён по умолчанию;
- атомарная запись → чтение возвращает ту же модель.

**Ручной сквозной (машина пользователя):** запустить хост из Xcode; открыть окно; сменить тему → пробел в Finder показывает новую; выключить просмотр JSON → пробел на `.json` → системный показ; включить обратно → снова наш.
