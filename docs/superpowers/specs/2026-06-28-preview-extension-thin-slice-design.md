# QuickLookers — расширение Preview, тонкий вертикальный срез (фаза 2)

**Дата:** 2026-06-28
**Статус:** утверждён, готов к написанию плана реализации
**Платформа:** macOS 13+, Xcode 26, Swift 6.3
**Предшествует:** дизайн всей системы — `2026-06-27-quicklookers-design.md`; движок реализован (фаза 1).

## Цель

Минимумом кода доказать, что весь продукт жизнеспособен: **пробел в Finder на файле кода → полноразмерное превью, нарисованное `QuickLookersEngine`, визуально один-в-один с VS Code.** Попутно снять показания по трём незакрытым spike из общего дизайна.

Это **тонкий вертикальный срез**, а не полная подсистема Preview. Намеренно отложено: кэш готового HTML, обрезка первого экрана, нативный путь Markdown, чтение настроек, App Group, GUI настроек. Всё это — следующие фазы.

## Что проверяем (spikes)

1. **Тёплый процесс.** Живёт ли процесс расширения между показами. Движок создаётся один раз на жизнь процесса (ленивый синглтон); на втором показе он уже горячий — это должно быть видно по времени и логам.
2. **Бюджет на реальном конвейере.** Замерить время «от вызова системы до готовой картинки» уже внутри расширения (с `WKWebView` и версткой), а не на голом движке, как в фазе 1.
3. **Возврат по UTI (лёгкая версия).** Убедиться, что на типе, который мы не обрабатываем, расширение не падает. Полноценный тест opt-in системных типов и возврата к родному превью macOS — в фазе настроек.

## Решения по объёму (зафиксировано в брейншторме)

- **Тонкий срез**, а не полная подсистема Preview.
- **XcodeGen**: проект описывается декларативно в `project.yml` (в git), `.xcodeproj` генерируется и в git не хранится. Причина: `project.pbxproj` нечитаем и не правится надёжно ни человеком, ни ассистентом; XcodeGen даёт понятный, ведущийся в git слой.
- **App Group отложен** до фазы менеджера. Расширение рисует из ресурсов, вшитых в пакет `QuickLookersEngine` (`Bundle.module`). Причина: App Group ничего из задач среза не обслуживает, зато требует provisioning-профиля и усложняет подпись. Без него подпись остаётся простой (личный Team, автоматический режим). Подпись локально всё равно обязательна — иначе macOS не загрузит расширение в свои процессы.

## Структура проекта

Движок остаётся **чистым SwiftPM-пакетом** (чтобы `swift test` работал как прежде). XcodeGen собирает вокруг него Xcode-проект с двумя таргетами.

```
Package.swift                  # движок — без изменений
Sources/QuickLookersEngine/    # без изменений
Tests/                         # без изменений
project.yml                    # НОВОЕ — спека XcodeGen (в git)
QuickLookers.xcodeproj         # генерируется, в .gitignore
App/                           # НОВОЕ — приложение-хост (заглушка-окно)
PreviewExtension/              # НОВОЕ — расширение Preview
  PreviewViewController.swift
  Info.plist
```

- **Хост-приложение** — пустое окно. Задача — быть контейнером, внутри которого система регистрирует расширение. GUI настроек придёт в фазе менеджера.
- **Расширение Preview** — линкует локальный пакет `QuickLookersEngine`, рисует из его вшитых ресурсов.
- `.xcodeproj` всегда пересоздаётся из `project.yml`.

## Поток показа (внутри расширения)

Расширение — `QLPreviewingController`. На один показ:

1. Система зовёт `preparePreviewOfFile(at: url)`.
2. Читаем содержимое файла; по расширению определяем язык (маленькая таблица соответствия).
3. Зовём движок: `код + язык + тема dark-plus → HTML` через `QuickLookersEngineFactory.makeDefault()`.
4. Оборачиваем HTML в минимальную страницу: фон цвета темы, моноширинный шрифт, сброс полей.
5. Грузим в `WKWebView` с **выключенным JavaScript** (вебвью только верстает статичный HTML).
6. Дёргаем completion-handler.

**Тёплый процесс:** движок — ленивый синглтон на жизнь процесса. Грамматики/темы грузятся один раз, лениво по языку, и остаются в памяти. Это и есть проверка spike 1.

## Набор для среза

- **Тема:** `dark-plus` (дефолтная тёмная VS Code) — эталон для сравнения.
- **Языки:** `swift`, `json`, `javascript` — те, на которые уже есть грамматики в пакете, и у каждого стабильный системный UTI:
  - Swift → `public.swift-source`
  - JSON → `public.json`
  - JavaScript → `com.netscape.javascript-source`
- Эти три UTI объявляем в `QLSupportedContentTypes` плиста расширения.

## Замеры spike

- В расширении — логирование через `os_log`: pid процесса, был ли движок уже тёплым на этом показе, время показа в миллисекундах.
- Читаем в Console.app. За один сеанс получаем ответ по «тёплому процессу» (spike 1) и «бюджету на реальном конвейере» (spike 2).

## Проверка работоспособности (end-to-end)

- `swift test` — зелёный (движок не трогали).
- `xcodegen generate` → `xcodebuild` собирает приложение + расширение без ошибок.
- **Ручной шаг пользователя** (только на его машине): один раз запустить хост-приложение (регистрирует расширение в системе), затем пробел на `.swift`/`.json`/`.js`-файле в Finder → увидеть подсветку, сравнить картинку с VS Code на теме Dark+.
- Логи spike смотрим в Console.app.

## Открытые технические точки (сверить в плане/на сборке)

- Загрузятся ли ресурсы пакета (`Bundle.module`) внутри бандла расширения. Обычно да; проверяется на первой сборке — часть spike по конвейеру.
- Точная сигнатура API `QLPreviewingController` / `preparePreviewOfFile` под Xcode 26 / macOS 26 — сверить по докам при написании плана.
- Подпись: личный Team в автоматическом режиме. Если регистрация расширения не подхватится — разобраться на этапе ручной проверки (вероятные причины: `pluginkit` не увидел бандл, приложение не в `/Applications` или не запускалось).

## Намеренно вне среза (следующие фазы)

- Кэш готового HTML в общем контейнере.
- Обрезка первого экрана и догрузка при прокрутке.
- Чтение настроек, выбор темы, светлая/тёмная по системе.
- App Group и наполнение контейнера менеджером.
- Расширение Thumbnail.
- Полноценный тест возврата к родному превью macOS по opt-in системным UTI.
