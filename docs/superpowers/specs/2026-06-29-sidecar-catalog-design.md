# Сайдкар-каталог (vsix-aware) — дизайн

**Дата:** 2026-06-29

## Зачем

После перехода грамматик на формат-массив [главная + встроенные] файлы стали
большими (rst ≈4 МБ, twig ≈3,7 МБ). `FileCatalogSource.loadCatalog()` читает и
парсит **все 218 грамматик (~41 МБ) + 54 темы** только ради `name` +
`displayName` каждого. Это не горячий путь превью (превью грузит одну
грамматику), а загрузка каталога **при открытии окна настроек** — там лишние
сотни миллисекунд, на холодном диске секунды.

Найдено `/simplify` фазы 4 как follow-up эффективности каталога.

## Что строим

Маленький **сайдкар-файл `catalog.json`** (~10 КБ) с метаданными каталога,
который генерится на шаге сборки. `FileCatalogSource` читает его вместо обхода
всех грамматик. Старый обход остаётся **фоллбэком**.

Сайдкар проектируется как **расширяемый индекс**: и шаг сборки, и будущий
импортёр `.vsix` пишут записи в том же формате; каталог = слияние всех
сайдкаров. Сам импорт `.vsix` — отдельная спека позже (он остаётся в исходном
дизайне `2026-06-27-quicklookers-design.md`).

## Архитектура

Каталог метаданных (`id`, `displayName`, `isDark`) выносится из больших файлов
грамматик/тем в один маленький JSON. Чтение каталога идёт по сайдкару; полный
обход директорий — страховка на случай отсутствия/повреждения сайдкара.

## Компоненты и поток данных

### 1. Шаг сборки — `js/extract-resources.mjs`

В существующих циклах извлечения уже есть нужные данные (массив грамматики,
объект темы). Добавляем сбор в один файл:

```jsonc
// Sources/QuickLookersEngine/Resources/catalog.json
{
  "languages": [{ "id": "swift", "displayName": "Swift" }, …218],
  "themes":    [{ "id": "dark-plus", "displayName": "Dark+", "isDark": true }, …54]
}
```

- `displayName` языка — из записи массива грамматики, где `name == id`
  (главная грамматика; в массиве может быть не первой), иначе `id`.
- `id` темы — `theme.name`; `displayName` — `theme.displayName ?? theme.name`;
  `isDark` — `theme.type === "dark"`.

Логика ровно та же, что сейчас в `FileCatalogSource`, но посчитанная **один раз
на сборке**. Файл — **артефакт сборки** (как `shiki-bundle.js`): коммитится,
руками не правят.

### 2. Доступ к ресурсу — `Sources/QuickLookersEngine/EngineResources.swift`

Новый метод:

```swift
public static func catalogSidecarURL() -> URL? {
    Bundle.module.url(forResource: "catalog", withExtension: "json")
}
```

Возвращает `nil`, если файла нет → включает фоллбэк.

### 3. Чтение каталога — `Sources/QuickLookersSettingsKit/CatalogSource.swift`

`FileCatalogSource` получает дополнительный параметр
`sidecarURLs: [URL] = []`. В `loadCatalog()`:

- есть хотя бы один читаемый и валидный сайдкар → каталог из слияния сайдкаров
  (быстрый путь);
- ни одного читаемого сайдкара → существующий полный обход директорий
  (фоллбэк; **код обхода не удаляем**).

**Формат сайдкара (декодируемый):**

```swift
struct CatalogSidecar: Decodable {
    struct Language: Decodable { let id: String; let displayName: String }
    struct Theme: Decodable { let id: String; let displayName: String; let isDark: Bool }
    let languages: [Language]
    let themes: [Theme]
}
```

**Слияние нескольких сайдкаров (задел под vsix):** `sidecarURLs` — список.
Сегодня приложение передаёт `[встроенный]`. Позже импортёр `.vsix` пишет
сайдкар-фрагмент в контейнер App Group и добавляет его в список. Слияние:
проходим сайдкары в порядке списка, копим в словарь по `id` — **последний
перекрывает** (импортированный пользователем перекрывает встроенный). Итог
сортируется по `id` (как сейчас). Сегодня список из одного — слияние тривиально,
но интерфейс готов.

Битый сайдкар (не декодируется) трактуется как отсутствующий: пропускаем его. Если
после пропусков ни одного валидного не осталось → фоллбэк-обход.

### 4. Подключение — `App/SettingsModel.swift`

Передаёт `sidecarURLs: [catalogSidecarURL]` (фильтруя `nil`).

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет сайдкара (`catalogSidecarURL() == nil` или пустой список) | Фоллбэк: полный обход директорий (нынешнее поведение) |
| Сайдкар не декодируется | Пропускаем этот сайдкар; если валидных не осталось — фоллбэк |
| Часть сайдкаров валидна | Сливаем валидные, битые игнорируем |

Каталог **никогда не пустеет** из-за проблем с сайдкаром.

## Тестирование (TDD, `swift test` в SettingsKit)

- сайдкар есть → каталог из него; `displayName` языков и `isDark` тем верны;
- сайдкара нет (пустой `sidecarURLs`) → фоллбэк-обход даёт тот же каталог, что и
  сейчас;
- битый сайдкар (мусорный JSON) → фоллбэк;
- два сайдкара с пересекающимися `id` → дедуп по `id`, последний перекрывает
  (форвард-совместимость с vsix);
- регенерируем настоящий `catalog.json` и проверяем: **218 языков / 54 темы**
  (страховка шага сборки).

## Глобальные ограничения

- **TDD строго**: падающий тест → запуск (падает) → реализация → запуск
  (зелёный) → коммит, по одному маленькому шагу.
- **Движок изолирован за протоколом** `HighlightEngine`; каталог/настройки — в
  `QuickLookersSettingsKit`, не знают про Shiki/JSC.
- **Всё офлайн**: сайдкар — в ресурсах пакета.
- `catalog.json` — **артефакт сборки**: генерится `extract-resources.mjs`, руками
  не правят (как `shiki-bundle.js`).
- Фоллбэк-обход директорий **не удаляется** — он страховка.
- Ветка отдельная, не `main` напрямую. Коммиты по-русски, трейлер
  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
