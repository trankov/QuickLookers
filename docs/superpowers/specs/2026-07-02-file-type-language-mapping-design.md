# Сопоставление файлов с подсветкой (UTI ↔ язык) — дизайн

Дата: 2026-07-02. Область: перехват в Finder и назначение языка.

## Проблема

Сейчас перехватывается ~23 типа из 218 языков библиотеки. **Большинство подсветок
не работает** — файлы просто не доходят до расширения. Причина установлена спайком
(см. ниже) и оказалась жёстче, чем предполагалось.

## Установленный факт (спайк parent-uti-preview, 2026-07-02)

Сопоставление `QLSupportedContentTypes` идёт по **точному листовому UTI**, а не по
конформансу вверх по дереву. Проверено вживую (macOS 26): объявление только
родителя `public.source-code` **не ловит** дочерние `public.swift-source` /
`public.python-script` / `org.go.source` — файлы остались у системы. Разведено от
конфаунда регистрации (канарейка `public.swift-source` при этом ловилась). Совпадает
с явной формулировкой Apple для Thumbnail. **Стратегия «широкий зонтик» отвергнута.**
Детали — `docs/superpowers/notes/2026-06-28-intercept-spikes.md` (Спайк A), урок —
в playbook (`reference/app-groups-and-containers.md`).

## Ментальная модель: два независимых слоя

Задачу нельзя решать одним механизмом — она распадается надвое:

- **Слой A — Маршрутизация** («дойдёт ли файл до нас»). Статичный список **точных
  листовых UTI** в Info.plist расширения. Меняется только пересборкой. Рантайм умеет
  лишь **сужать** (отказаться рисовать), не добавлять.
- **Слой B — Назначение языка** («чем красить дошедший файл»). Чистый рантайм:
  таблицы `расширение → язык` и `имя файла → язык`, редактируемые пользователем.
  Здесь живёт UI.

Путать слои нельзя: UI-таблица осмысленна только для того, что физически дошло
(объявлено в Слое A).

## Слой A — стратегия объявления «максимум минус csv/md»

Список UTI собирается из трёх наборов — вместе дают широкий и машинно-устойчивый
невод:

1. **`public.plain-text`** — точным совпадением ловит `.txt`, конфиги и (предполож.)
   безрасширенные/неизвестные текстовые файлы. Машинно-независим. Главный «сборщик
   хвоста».
2. **Курированный набор стабильных `public.*`** (swift, python, c, cpp, ruby, php,
   perl, javascript, json, yaml, xml, shell, …) — Apple их всегда поставляет,
   машинно-независимы.
3. **Best-effort вендорные reverse-DNS** (`org.go.source`, `org.rust-lang.rust`, …) —
   помогают на машинах с тулчейном, где файл получает *свой* тип и проходит мимо
   plain-text. На чистой машине безвредны: там файл упадёт в plain-text и всё равно
   пойман.

Почему не резолвим все 202 расширения → UTI автоматически: результат `UTType(
filenameExtension:)` **машинно-зависим** (зависит от установленных приложений).
Запекать dyn.*/вендорные строки с dev-машины в Info.plist нельзя — на чужой машине
они не совпадут. Поэтому Слой A = машинно-независимое ядро (`public.*` + plain-text)
+ безвредный best-effort вендорный список. Устойчивость охвата несёт `public.plain-text`.

**Исключения csv/md** — не попадают ни в один набор → остаются ОС/соседнему
расширению. «Отдать системе» физически означает **не объявлять** тип (иначе, объявив
и отказавшись, получим дженерик, а не нативное превью — спайк C).

### Хвост закрыт (Задача 5b, 2026-07-03)

Спайк E (`docs/superpowers/notes/2026-06-28-intercept-spikes.md`) установил механику
хвоста тремя фактами: у UTI нет тега на целое имя файла (только
`filenameExtension`/`mimeType` — официальные доки Apple), поэтому безрасширенные
файлы своим UTI не поймать, только общим неводом; расширение, занятое конкурентом
(эталон — sbarex), объявлением своего UTI не отнять — держит сам факт экспорта типа
в LaunchServices, даже когда QL-расширение конкурента выключено; а вот свободное
(`dyn.*`) расширение свой UTI забирает чисто — подтверждено живым тестом (удалили
sbarex → `.nim` переключился на наш тип, показалась наша подсветка). На этих фактах
хвост закрыт тремя механизмами (все — правки `project.yml`, без изменения рантайма):

1. **Невод `public.data`** — безрасширенные конфиги (`Dockerfile`, `.gitignore`,
   `Makefile`) получают листовой UTI `public.data`; объявлен в
   `QLSupportedContentTypes`. Язык — по имени файла из `associations.json`; бинарь
   (не-UTF-8) бросает → системный дженерик. Неизвестные *расширения* (лист `dyn.*`)
   этот невод не ловит.
2. **Выверенные системные UTI** — около 30 UTI, где системный тип и есть код/текст
   (Pascal, Fortran, GLSL, Objective-C, HTML/CSS/XML, Assembly, Protobuf, HLSL,
   шелл-скрипты и т. д.), плюс два намеренных перехвата «ложных друзей»: `.ts` →
   typescript (система метит видео MPEG-2 transport stream) и `.r` → R (Apple Rez).
   Другие «ложные друзья» с настоящим не-кодом за расширением (`.app`, `.pf`,
   `.dds`, `.gp`, `.potx`, `.mts`…) **намеренно не объявлены** — объявить значило бы
   сломать чужие настоящие файлы этого типа.
3. **Собственный экспортируемый UTI `com.quicklookers.source-code`** — один тип на
   все свободные (`dyn.*`) расширения датасета: 652 штуки (`kt`, `dart`, `graphql`,
   `nim`, `zig`, `vala`, `gleam`, `solidity`…), `conformsTo public.source-code +
   public.plain-text`. Список сгенерирован `Scripts/audit-extension-utis.swift
   --emit-tags` по снимку `docs/superpowers/notes/2026-07-03-extension-uti-audit.md`.
   Экспортёром типа стал **хост-таргет** (тип должен откуда-то экспортироваться,
   расширение сам тип не декларирует) — хост перешёл на явный `info:`-блок в
   `project.yml` (`GENERATE_INFOPLIST_FILE: NO`, артефакт — `App/Info.plist`). Язык
   внутри — по расширению.

   **Грабля регистрации (важно перед повторным аудитом):** после сборки хоста
   LaunchServices регистрирует наш `com.quicklookers.source-code`, и на машине
   разработки эти 652 расширения начинают резолвиться уже в наш тип, а не в
   `dyn.*` → повторный прогон `audit-extension-utis.swift --emit-tags` покажет почти
   пусто (та же природа, что артефакт `.nim` в снимке аудита). Аудит гнать **до**
   сборки или на чистой машине; актуальный список — из снимка, не из живого прогона
   после сборки.

**Осознанное ограничение:** расширение, занятое установленным сторонним
QL-приложением (в спайке — `.nim` у sbarex), нашим UTI не отнять — механизм 3
работает только на свободных расширениях. У пользователя без конкурирующего
приложения то же расширение свободно и достаётся нам. Ссылаться на чужой UTI
конкурента в своём Info.plist намеренно не делаем — хрупко, завязано на конкретную
стороннюю программу, которой на других машинах может не быть.

### Как список A попадает в Info.plist

Список генерируется на сборке (не правится руками) из курированной карты стабильных
UTI + `public.plain-text` и вставляется в `QLSupportedContentTypes` расширения через
конвейер XcodeGen. Точный механизм (инъекция в `project.yml` либо генерируемый
base-plist) — в плане.

## Слой B — данные, рантайм, UI

### Датасет соответствий

Источник Shiki для соответствий «расширение → язык» **непригоден**: `fileTypes` есть
лишь у 91 из 218 грамматик, а `bundledLanguagesInfo` несёт только `{id, name}` (0
расширений). Проверено.

**Источник — github-linguist `languages.yml`** (лицензия MIT, офлайн). Богат:
тысячи расширений, поле `filenames` (Dockerfile, Makefile, Gemfile…), алиасы. Снимок
`languages.yml` **вендорится** в `js/` (пиннится ради воспроизводимости и офлайна),
не тянется из сети в рантайме.

**Генерация** (новый шаг сборки, рядом с `extract-resources.mjs`): для каждого
Shiki-id собрать `{ shikiId, extensions[], filenames[] }` из
`linguist (основное) ∪ fileTypes грамматики (дополнение) ∪ ручной словарь исключений`
(для Shiki-специфичных id вроде `angular-ts`, `glimmer-js`, что не матчатся в
linguist). Результат — сгенерированный **`associations.json`** в бандле пакета.
Единый источник и для генерации Слоя A, и для рантайма Слоя B.

### Рантайм-разрешение

При показе файла:

1. По расширению (или, для безрасширенных, по имени файла) найти `shikiId` в
   `associations.json`, наложив пользовательские правки из `settings.json`.
2. Если формат **включён** для просмотра → красить найденным языком.
3. Если формат **выключен** или язык не найден → рисовать **нейтральным
   моноширинным текстом** (без подсветки), а не отдавать в дженерик. Это визуально
   ближе к нативному текстовому превью и лучше дженерика. (Изменение поведения против
   спайка C, где отказ давал дженерик.)
4. Нечитаемый (не-UTF-8) файл → как и раньше, бросок → системный дженерик.

### UI — эволюция вкладки «Просмотр в Finder»

Вкладка перестраивается в **таблицу-список на всю ширину** (`List`, как в фазе 6) со
столбцами:

- **`Расширение / имя файла`** — ключ правила (`.py`, `.conf`, `Dockerfile`).
- **`Язык`** — на какой Shiki-грамматике красить (выбор из каталога).
- **`Просмотр`** — тумблер вкл/выкл (`.toggleStyle(.switch)`, `.controlSize(.small)`).

Плюс: поиск по таблице; **добавление своего правила** (`.myext → python`,
`.conf → ini`); удаление/выключение ненужного. Строки без расширения (Dockerfile)
матчатся по имени. Правки пишутся в `settings.json` поверх сгенерированного датасета
(датасет — база, настройки — оверлей).

## Честные пределы (обязаны быть словами в UI)

- **«Подключить формат» в рантайме невозможно.** Не объявленный на сборке UTI до нас
  не доходит; тумблер в UI — только опт-аут поверх объявленного.
- **Выключенный формат рисуется нейтральным текстом**, полностью системного
  (нативного) превью в рантайме не вернуть. Настоящее «отдать нативу» = не объявлять
  тип (csv/md) либо снять галочку со всего расширения в Системных настройках.

## Затрагиваемый код

- **`DeclaredTypes.swift`** — расцепляется: UTI-список уходит в генерацию (Слой A),
  разрешение `расширение/имя → язык` становится data-driven из `associations.json`
  (Слой B).
- **`ManagerSettings.swift`** — модель настроек расширяется: пользовательские правила
  (`расширение/имя → язык`) и опт-аут по правилу/формату. Пользователей ещё нет →
  схему меняем без миграции (как в фазе 6).
- **`PreviewViewController.swift`** — ветка «нейтральный текст» для
  выключенного/неизвестного; чтение оверлея настроек.
- **`QuickLookersPreviewKit`** — нейтральная (без Shiki) HTML-страница как чистая
  тестируемая функция рядом с `previewPageHTML`.
- **`FileTypesTab.swift`** + модель окна — таблица правил, поиск, добавление.
- **`js/`** — новый `generate-associations.mjs` + вендоренный `languages.yml`;
  `associations.json` в ресурсах.
- **`project.yml` / Info.plist** — генерируемый `QLSupportedContentTypes`; хвост
  (Задача 5b) добавил явный `info:`-блок хоста (`App/Info.plist`, артефакт
  XcodeGen) с `UTExportedTypeDeclarations`.
- **`Scripts/audit-extension-utis.swift`** (Задача 5b) — dev-утилита: по
  `associations.json` резолвит листовой UTI каждого расширения и категоризирует
  под три механизма хвоста; режим `--emit-tags` печатает список для механизма 3.

## Тестирование (TDD, слоистый набор)

- **Генерация датасета** (node-смоук): каждый Shiki-id получает непустой набор
  расширений *или* явно помечен как «без расширения»; известные пары
  (`swift→swift`, `Dockerfile→docker`) присутствуют.
- **Разрешение языка** (`swift test`, PreviewKit/SettingsKit): расширение → язык;
  имя файла → язык; оверлей пользователя перекрывает базу; выключенный формат →
  нейтральный путь; неизвестное расширение → нейтральный путь.
- **Нейтральная страница** (PreviewKit): экранирование, отсутствие Shiki-разметки,
  моноширинный шрифт.
- **Слой A** — проверяется живым спайком (объявленный список ловит целевые файлы),
  не юнит-тестом.

## Открытый эмпирический вопрос (спайк по ходу плана)

Ловит ли `public.plain-text` **безрасширенный `Dockerfile`** и **неизвестные
расширения**, или система даёт им `dyn.*` / `public.data`? От ответа зависит, достаёт
ли невод этот хвост сразу, или части хвоста нужен собственный UTI раньше Task 5b.
Проверяется маленьким спайком (объявить plain-text, положить `Dockerfile` и
`foo.неизвестное`, снять пробелом), результат — в заметку.

## Вне области

- Определение языка по содержимому/shebang (`firstLineMatch` в грамматиках есть —
  задел на будущее, не сейчас).
- Markdown (вне продукта) и csv (лучше показывает ОС) — сознательно не наши.
- Расширения, занятые установленным сторонним QL-приложением (в спайке — `.nim` у
  sbarex) — собственный UTI их не отнимает; принятое ограничение (Спайк E).
