# Импорт из `.vsix` (темы + грамматики) — дизайн

**Дата:** 2026-06-29

## Зачем

Главное приложение-менеджер пока показывает только встроенную библиотеку Shiki
(218 языков / 54 темы). Исходный дизайн (`2026-06-27-quicklookers-design.md`)
предусматривает пополнение библиотеки из `.vsix` — расширений VS Code, скачанных
пользователем самостоятельно с маркетплейса. Эта спека описывает **импорт из
`.vsix`-файла**: распаковать, прочитать `package.json`, нормализовать
объявленные грамматики и темы, положить в общий контейнер так, чтобы движок
красил ими так же, как встроенными.

**Вне области этой спеки:** «как в моём редакторе» (поиск установленных
VS Code-форков → копирование активной темы + шрифта) — отдельная спека, вместе
с под-фичей «настройки шрифта». Импорт из `.vsix`-файла и тот сценарий
разъехались по механизму и цели; здесь только файловый импорт.

## Решения (зафиксированы при брейншторме)

- **Источник:** `.vsix`-файл, выбранный пользователем через файл-пикер.
- **Содержимое:** и темы, и грамматики.
- **Форматы грамматик:** `.tmLanguage.json`/`.json` (как есть) и
  `.tmLanguage`/`.plist` (XML, перекодируем plist→JSON через Foundation).
- **Распаковка ZIP:** системная `libarchive` через C-мостик (без сторонних
  зависимостей; в Foundation родного распаковщика ZIP нет, спавн `unzip`
  песочница блокирует).
- **Конфликт `id`:** импорт перекрывает встроенное (контейнер старше бандла по
  `id`); удаление импорта возвращает встроенное.
- **Управление:** импортированное помечается в существующих вкладках
  «Форматы»/«Темы» (метка + крестик удаления); кнопка «Импортировать…» там же.
- **Импортируем всё**, что объявлено в `.vsix` (тема-пак с 6 вариантами — все 6),
  без выбора-списка; сводку показываем после.
- **Вложенные грамматики (вариант B):** дособираем недостающие вложенные языки
  из самого `.vsix` и из встроенной библиотеки.

## Архитектура и модули

Импорт — **чистая логика**, отделённая от записи в контейнер App Group.

- **`CLibArchive`** — новый системный таргет SwiftPM: module map над системной
  `/usr/lib/libarchive` (заголовок `archive.h` + `archive_entry.h`). Сторонних
  зависимостей нет.
- **`QuickLookersImportKit`** — новый пакетный таргет: распаковка нужных записей
  `.vsix` через `CLibArchive`, парсинг `package.json`, нормализация грамматик и
  тем (включая дособирание вложенных). На вход — путь к `.vsix` и путь к
  встроенным грамматикам (для дособирания вложенных). На выход —
  **готовые в памяти артефакты**: для каждого элемента `id`, тип
  (грамматика/тема), байты нормализованного JSON, запись для сайдкара
  (`{id, displayName}` или `{id, displayName, isDark}`), плюс список пропусков с
  причинами. Контейнер App Group ImportKit **не знает** → тестируется
  `swift test` без подписи/песочницы.
- **Приложение** (`QuickLookersApp`): файл-пикер `.vsix`, вызов ImportKit,
  **запись** артефактов в контейнер (приложение писать в групповой контейнер
  может — расширение нет, см. рантайм-находки фазы 5), обновление UI и сводка.

Граница: ImportKit производит артефакты, но не пишет их. Решение «куда писать»
(контейнер App Group) и сам ввод-вывод — в приложении/`QuickLookersSettingsKit`.

## Раскладка контейнера

Импортированная библиотека — в подпапке `library/` группового контейнера
(`quickLookersContainerURL()` из `QuickLookersSettingsKit`):

```
<контейнер App Group>/
  settings.json                     # уже есть (пишет приложение)
  library/
    grammars/<id>.json              # импортированные грамматики (форма как у бандла)
    themes/<id>.json                # импортированные темы
    catalog-imported.json           # сайдкар-фрагмент: {languages:[…], themes:[…]}
```

## Поток данных

```
.vsix (ZIP) ─libarchive─▶ extension/package.json
                          ├─ contributes.grammars[] {language, scopeName, path}
                          ├─ contributes.themes[]   {label, uiTheme, path}
                          └─ contributes.languages[] {id, aliases}   (для displayName)
       ─libarchive─▶ файлы грамматик/тем по path (внутри extension/…)
       ─normalize─▶ см. «Нормализация»
       ─app пишет─▶ library/grammars/<id>.json, library/themes/<id>.json,
                    обновляет library/catalog-imported.json
```

`.vsix` — это ZIP, где содержимое расширения лежит под префиксом `extension/`.
`path` в `contributes.*` даётся относительно корня расширения; реальная запись в
архиве — `extension/<path>`.

## Нормализация

### Грамматика
1. Прочитать файл по `path`. Если `.tmLanguage`/`.plist` (XML plist) —
   перекодировать `PropertyListSerialization` → `JSONSerialization`. Если JSON —
   как есть.
2. `id` грамматики = `contributes.grammars[].language` (id языка).
3. `displayName` = первый алиас из `contributes.languages[]` с тем же `id`, иначе
   сам `id`.
4. **Дособирание вложенных (вариант B):** собрать грамматику в массив
   `[главная + все транзитивно вложенные]`, как у встроенных:
   - стартуем с грамматик(и) из этого `.vsix`;
   - транзитивно идём по `embeddedLangs`;
   - каждый недостающий вложенный язык берём сначала из других грамматик этого
     `.vsix`, затем из встроенной библиотеки: читаем `<lang>.json` (он уже сам
     закрытый массив с его вложенными) и вливаем целиком;
   - дедуп по `name`.
5. Записать массив как `library/grammars/<id>.json`.

**Ограничения (паритет со встроенными, не хуже):** вложенный язык, которого нет
ни в `.vsix`, ни в библиотеке → его блок без подсветки. Ленивые вложенные
(`embeddedLangsLazy`) не дособираем → глубоко-вложенные редкие фрагменты (yaml
внутри vue) могут остаться бледными — это существующий предел встроенных
грамматик.

### Тема
1. Прочитать файл по `path` (тема VS Code — JSON; Shiki использует темы VS Code
   напрямую).
2. `id` темы = слаг от `contributes.themes[].label` (нижний регистр, пробелы→`-`,
   убрать небезопасные символы); при коллизии слага в пределах одного импорта —
   суффикс `-2`, `-3`.
3. `displayName` = `label`.
4. `isDark` = `uiTheme ∈ {vs-dark, hc-black}` (иначе светлая).
5. Записать как `library/themes/<id>.json`.

**Ограничение:** тема со ссылкой `include` на базовую тему (редко) импортируется
как есть; если база отсутствует — цвета могут быть неполными. Осознанный край
первой версии.

## Чтение движком из контейнера

`QuickLookersEngineFactory.makeDefault(importedGrammarsDir:importedThemesDir:)` —
параметры опциональны (`URL?`, `nil` → только бандл). Появляется **композитный
провайдер**: для `<id>.json` сначала ищет в каталоге контейнера, затем в бандле.

- И приложение, и расширение Preview строят движок с этими путями
  (`library/grammars`, `library/themes` из `quickLookersContainerURL()`).
- Перекрытие по `id` получается само: контейнер старше бандла.
- Расширению групповой контейнер доступен **на чтение** (импортированные
  грамматики/темы там читаются так же, как `settings.json`).

Существующий `BundledGrammarProvider`/`BundledThemeProvider` остаётся; новый
`CompositeGrammarProvider`/`CompositeThemeProvider` оборачивает «контейнер →
бандл».

## Каталог настроек

Сайдкар уже спроектирован под это (см. `2026-06-29-sidecar-catalog-design.md`):

- импорт пишет/обновляет `library/catalog-imported.json` того же формата;
- приложение строит `FileCatalogSource` с
  `sidecarURLs: [встроенный, импортированный]`;
- слияние — последний (импортированный) перекрывает по `id`; уже реализовано.

В UI импортированные элементы помечаются в списках вкладок «Форматы»/«Темы»
(метка «импорт» + крестик). Признак «импортированный» = `id` присутствует в
импортированном сайдкаре.

## Удаление

Убрать `library/grammars/<id>.json` (или `themes/<id>.json`) и запись из
`catalog-imported.json`. Если `id` перекрывал встроенный — встроенный возвращается
сам (файла в контейнере нет → композитный провайдер падает на бандл). Если `id`
был только импортированным — пропадает из каталога.

## Обработка ошибок (по-записно, не «всё или ничего»)

| Ситуация | Поведение |
|---|---|
| Файл не `.vsix`/не ZIP, libarchive не открыл | Отказ, ничего не пишем, внятное сообщение |
| Нет `extension/package.json` или он не парсится | Отказ, ничего не пишем |
| Нет ни `contributes.grammars`, ни `contributes.themes` | Отказ: «в расширении нет тем и грамматик» |
| Одна тема/грамматика: нет файла по `path`, битый JSON/plist | Пропуск этой записи, остальные импортируются |
| Вложенный язык не нашёлся нигде | Грамматика пишется, его блок без подсветки |
| Итог: импортировано N, пропущено M | Сводка пользователю с причинами пропусков |

Запись в контейнер атомарная (через временный файл + замена), чтобы частичный
сбой не оставил битый `<id>.json`.

## Тестирование (TDD)

**`QuickLookersImportKit` под `swift test`** (фикстуры — маленькие `.vsix` и
файлы в ресурсах тестов):
- распаковка нужных записей из тестового `.vsix` через `CLibArchive` (deflate и
  stored);
- парсинг `package.json` → списки грамматик/тем;
- нормализация JSON-темы: `id`-слаг, `displayName`, `isDark` из `uiTheme`;
- нормализация plist-грамматики: plist→JSON;
- дособирание вложенных: импорт «vue»-подобной грамматики с `embeddedLangs` →
  массив включает дотянутые из встроенной библиотеки языки (дедуп по `name`);
- частичный успех: один битый элемент пропущен, остальные импортированы;
- отказы: не-ZIP, нет `package.json`, нет `contributes.*`.

**Движок:** композитный провайдер — контейнер перекрывает бандл, фоллбэк на
бандл при отсутствии файла в контейнере.

**Приложение** (сборка без подписи): запись артефактов в контейнер, появление
импортированного в каталоге, удаление возвращает встроенное.

## Глобальные ограничения

- **TDD строго:** падающий тест → запуск (падает) → реализация → запуск
  (зелёный) → коммит, по одному маленькому шагу.
- **Движок изолирован за протоколом** `HighlightEngine`; потребители не знают про
  Shiki/JSC. ImportKit не зависит от движка во время показа — только читает
  встроенные грамматики как файлы для дособирания.
- **Без сторонних зависимостей:** распаковка — системная `libarchive`; plist→JSON
  — Foundation. Только Shiki остаётся как было.
- **Всё офлайн:** импорт не использует сеть (`.vsix` уже скачан пользователем).
- **Запись в групповой контейнер — только приложение.** Расширение Preview
  контейнер лишь читает (подтверждено рантайм-находками фазы 5).
- **App Sandbox сохраняется** у обоих таргетов; импорт работает в песочнице
  приложения (файл-пикер даёт доступ к выбранному `.vsix`).
- Отдельная ветка, не `main` напрямую. Коммиты по-русски, трейлер
  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
