# Спайки перехвата в Finder — итоги (macOS 26 Tahoe, Darwin 25.5.0)

Проверено вручную пользователем на сборке Task 5a (объявлены 23 резолверных
системных UTI в `QLSupportedContentTypes`, без собственных UTI).

## Спайк B — кто побеждает над системой (С2)

**Вопрос:** если объявить точный UTI типа, который превьюит и система, — кто
покажет превью?

**Результат:** **побеждаем мы.** Для `public.json` и `public.yaml` (система
умеет показывать их текстом) по пробелу показалось наше подсвеченное превью, а
не системное.

**Вывод:** объявленный нами точный системный UTI перехватывает показ у системы.

## Граница «не объявлено = системе»

**Результат:** незаявленные `.ts`, `.r`, `.kt`, `.dart`, `.txt` остались за
системой/родным превью. Важно: `.ts` система типизирует как
`public.mpeg-2-transport-stream` (видео) — показ не сломался, просто остался
системным.

**Вывод:** чтобы отдать тип системе — достаточно его не объявлять.

## Спайк C — поведение отказа

**Вопрос:** когда расширение отказывается рисовать объявленный тип (язык
выключен в настройках) — что показывает Finder?

**Результат:** показалось **общее системное превью — крупная иконка файла с
мелким текстом**. Не пустой экран и не спиннер. После возврата тумблера наше
превью восстановилось.

**Вывод:** рантайм-отказ **безопасен** — Finder деградирует до системного
дженерик-превью (иконка+текст), показ не виснет. Это НЕ богатое родное превью
(текст с разметкой), но и не поломка. Значит рантайм-opt-out по языку допустим
как «показать дженерик вместо нашей подсветки».

## Спайк A — нужен ли точный UTI (С1) — ЗАКРЫТ 2026-07-02

**Проверено вживую (macOS 26, Darwin 25.5.0).** Раунд 1: в `QLSupportedContentTypes`
объявлен ТОЛЬКО родитель `public.source-code`. Файлы `.swift`/`.py`/`.go` (все
конформны source-code по `kMDItemContentTypeTree`) и контроль `.txt` — **все
остались у системы**, наше превью не показалось.

Раунд 2 (разведение конфаунда регистрации): объявлены родитель `public.source-code`
И один листовой `public.swift-source`. Результат: **`.swift` → наше, `.py`/`.go` →
система**. `.swift`-канарейка доказывает, что расширение зарегистрировано и
вызывается; значит `.py`/`.go` остались у системы именно потому, что родитель их
не ловит.

**Вывод:** сопоставление `QLSupportedContentTypes` идёт по **точному листовому
UTI**, а не по конформансу вверх. Зонтичный родитель (`public.source-code`,
`public.script`, `public.text`) охвата НЕ даёт — нужно перечислять точные UTI.
Совпадает с явной формулировкой Apple для Thumbnail («not sufficient to list a
parent UTI»). **Стратегия «широкий зонтик» отвергнута.** Урок вынесен в playbook
(`reference/app-groups-and-containers.md`).

## Машинная зависимость объявленных UTI (важная оговорка)

Спайки и резолвер запускались на dev-машине с установленными тулчейнами.
Из объявленных 23 UTI базово-системные — только `public.*`
(python/c/cpp/swift/php/ruby/perl/yaml/toml/json/sql/tsx) и
`com.netscape.javascript-source`. Вендорные reverse-DNS — `org.go.source`,
`org.rust-lang.rust`, `org.scala.source`, `org.vuejs.vue`, `org.nodejs.cjs`,
`com.microsoft.csharp-source`, `com.sun.java-source`, `com.adobe.jsx` —
зарегистрированы установленными приложениями. **На чистой macOS без этих
приложений `.go`/`.rs`/`.scala`/`.vue`/`.cjs`/`.jsx` могут не перехватываться**
(файл получит `public.plain-text`/`dyn.*`, и наш UTI не совпадёт). Группа A на
нашей машине перехватывается — для текущей цели (разнообразие под оптимизацию)
этого достаточно. Дистрибутив-робастность — собственными
`UTExportedTypeDeclarations` для этих расширений (расширение Task 5b), позже.

## Следствия для Task 5b (собственные UTI для сломанных расширений)

Расширения, отложенные в Task 4, по типу системной типизации делятся так
(гипотеза, проверяется в Task 5b объявлением своих UTI и ручным тестом):

- **Не заявлены никем (резолвер дал `dyn.*`):** `kt`, `kts`, `graphql`, `gql`.
  Тип не принадлежит никакому приложению → наш экспортируемый UTI, привязанный
  по расширению, **должен стать предпочтительным** → ожидаем перехват.
- **Заняты системным built-in:** `ts` → `public.mpeg-2-transport-stream`,
  `r` → `com.apple.rez-source`. Наш экспортируемый UTI, вероятно, **не
  переопределит** системный тип → ожидаем, что перехвата НЕ будет
  (совпадает с опытом sbarex про «зарезервированные» типы). Проверить.
- **Занят сторонним приложением:** `dart` → `org.sbarex.dart` (установлен
  sbarex). Спор двух претендентов — исход неясен. Проверить.
- **`dockerfile`:** перехват по имени файла, не расширению — `public.filename-extension`
  не подходит; отдельный механизм или отложить.

## Спайк D — невод public.plain-text (2026-07-02)

**Статус: PENDING — протокол ниже подготовлен, живой прогон в Finder делает
пользователь** (у агента нет доступа к Finder/GUI).

**Гипотеза.** `project.yml` теперь объявляет `public.plain-text` первой
строкой `QLSupportedContentTypes` (22 существующих UTI — без изменений).
Раз сопоставление у QuickLook идёт по точному листовому UTI (закрыто Спайком
A), а не по конформансу, ожидание такое:

- Файлы, чей точный листовой UTI и есть `public.plain-text` (безрасширенные
  вроде `Dockerfile`, неизвестные расширения, обычный `.txt`), теперь должны
  попадать **к нам** — невод «хвоста».
- Файлы с собственным более специфичным листовым UTI (`.csv` →
  `public.comma-separated-values-text`, `.md` →
  `net.daringfireball.markdown`) **не переходят к нам** — их точный лист не
  совпадает с `public.plain-text`, они остаются системе/соседнему расширению
  (FluxMarkdown и т. п.).

**Протокол (Шаг 3 брифа, выполняет пользователь):**

1. В Xcode ⌘R — запустить хост-приложение, чтобы `pkd` перерегистрировал
   расширение с новым списком UTI.
2. На Рабочем столе создать пять файлов:
   - `Dockerfile` (без расширения, текст `FROM alpine`)
   - `foo.неизвестное` (произвольный текст)
   - `note.txt` (произвольный текст)
   - `data.csv` (произвольный CSV)
   - `readme.md` (произвольный markdown)
3. По каждому файлу — выделить в Finder и нажать пробел (Quick Look).
   Зафиксировать, чьё превью показалось: наше (нейтральный текст или, если
   `resolvePreview` нашёл язык по имени, подсветка) или системное дженерик.
4. Параллельно смотреть лог:
   `/usr/bin/log stream --info --predicate 'subsystem == "com.quicklookers.preview"'`

5. Заполнить колонку «факт» в таблице ниже и, если что-то разошлось с

### Живой прогон Спайка D — ФАКТ (2026-07-02, macOS 26, sbarex установлен)

Резолвили реальный листовой UTI файлов через `URLResourceValues.contentType`
(именно по листу идёт перехват — установлено Спайком A):

| Файл | Листовой UTI | Наш невод берёт | Почему |
|---|---|---|---|
| `Dockerfile` | `public.data` | НЕТ | macOS не видит его текстом → generic-данные; `public.plain-text` мимо (точный лист) |
| `.gitignore` | `public.data` | НЕТ | то же — generic-данные, не текст |
| `foo.nim` | `org.sbarex.nim` | НЕТ | `.nim` занял установленный sbarex своим UTI; лист не plain-text |
| `note.txt` | `public.plain-text` | ДА (ожид.) | настоящий текстовый лист |
| `README` (без расш.) | `public.plain-text` | ДА (ожид.) | безрасширенный, но система опознаёт как текст |
| `data.csv` | `public.comma-separated-values-text` | НЕТ (верно) | свой лист → остаётся системе |

**Вывод (ответ на открытый вопрос фазы):** невод `public.plain-text` ловит ТОЛЬКО
файлы, которые сама macOS уже типизирует как простой текст (`.txt`, `README`,
`LICENSE`…). Он НЕ ловит:
- безрасширенные конфиги, которые система метит `public.data` (Dockerfile, .gitignore) —
  объявить `public.data` нельзя (это перехват всех файлов, включая бинарь/картинки);
  нужен перехват ПО ИМЕНИ ФАЙЛА, для которого у UTI нет чистого механизма → отдельная задача;
- расширения, которые заняты сторонним QL-приложением (sbarex: `.nim`, `.dart` и др.) или
  которым система даёт `dyn.*` — нужен собственный `UTExportedTypeDeclarations` (Задача 5b).

Итог: Слой A этой фазы даёт подсветку для настоящих текстовых файлов и 23 объявленных
UTI. Длинный хвост (Dockerfile-по-имени, sbarex/dyn-расширения) — материал Задачи 5b,
у неё своя реальная сложность (public.data-лист, конфликт с sbarex, filename-перехват).


### Спайк E — хвост: свой UTI против конкурента + невод public.data (2026-07-03, macOS 26)

Разобрали приём эталона (sbarex Syntax Highlight): в его Info.plist **142
экспортируемых + 29 импортируемых UTI**, и во всех тегах — только
`public.filename-extension` (170), `public.mime-type` (8), `com.apple.ostype`
(2). **Тега на «целое имя файла» нет ни одного** — даже `com.docker.dockerfile`
у них привязан к расширению `.dockerfile`, а не к имени `Dockerfile`. Значит
безрасширенные файлы никаким объявлением UTI не поймать в принципе; sbarex ловит
их своей фичей «Plain files» через общие `public.data`/`public.content` +
`/usr/bin/file`.

**Сборка спайка** (ветка `spike/uti-tail`): хост объявил свой
`com.quicklookers.nim-source` (расширение `nim`, конформанс public.source-code);
расширение добавило в `QLSupportedContentTypes` этот UTI и `public.data`.

**Живой прогон (sbarex установлен), листовые UTI + факт показа:**

Важно: QL-расширение sbarex в системных настройках было **ОТКЛЮЧЕНО**. Значит
`foo.nim` показал **не sbarex, а системный дженерик** (лист `org.sbarex.nim`, но
ни один *включённый* обработчик его не держит). Экспорт типа в LaunchServices и
включённость QL-расширения — разные оси.

| Файл | Листовой UTI | Показал | Вывод |
|---|---|---|---|
| `foo.nim` | `org.sbarex.nim` | **системный дженерик** (расширение sbarex выключено) | наш свой UTI **не вытеснил** экспорт sbarex из сопоставления `.nim`→UTI |
| `Dockerfile` | `public.data` | **мы**, `lang=docker` | невод ловит безрасширенные ✓ |
| `.gitignore` | `public.data` | мы (нейтраль) | невод ловит ✓ |
| `mystery.xyz` | `dyn.ah62…` | никто (знак «?») | невод **не** ловит неизвестные расширения |
| `note.txt` | `public.plain-text` | мы (нейтраль) | как в Спайке D ✓ |
| `blob` (бинарь) | `public.data` | никто (знак «?») | пришёл к нам → не-UTF-8 → отказ → системный дженерик ✓ |

**Выводы (железные):**

1. **Наш экспорт не вытеснил чужой из сопоставления `.nim`→UTI.** Объявили свой
   UTI на `.nim` — система всё равно оставила листом `org.sbarex.nim`, наш тип
   даже не в дереве. Причём удерживает лист **сам факт установленного приложения,
   экспортировавшего тип** — QL-расширение sbarex при этом ВЫКЛЮЧЕНО. То есть
   экспорт типа (LaunchServices) и включённость QL-расширения — разные оси; чтобы
   освободить `.nim`, приложение надо **удалить целиком**, не просто выключить.
   **ОТВЕРГНУТО как продуктовый путь:** ссылаться на чужой `org.sbarex.nim` в своём
   `QLSupportedContentTypes` — НЕ делаем. sbarex к продукту отношения не имеет, на
   чужих машинах его нет, закладка на конкретного конкурента хрупка. Занятое
   конкурентом расширение — просто принятое ограничение (редкость; на чистой машине
   расширение свободно и достаётся нашему UTI).
2. **Свободное расширение свой UTI забирает чисто.** Незанятое расширение система
   метит `dyn.*` (см. `mystery.xyz`). Объяви мы на него свой UTI — лист станет
   нашим. То есть механизм «свой UTI» работает для **свободных** расширений
   (`dyn.*`), не для отъёма занятых. → у пользователя без конкурента то же `.nim`
   свободно и достанется нам.
   **ПОДТВЕРЖДЕНО ВЖИВУЮ (2026-07-03):** удалили sbarex целиком (приложение +
   очистка Корзины — LS держал бандл из `~/.Trash`!) → `URLResourceValues.contentType`
   для `foo.nim` переключился `org.sbarex.nim` → **`com.quicklookers.nim-source`**,
   по пробелу показалось НАШЕ превью с подсветкой Nim. Механизм 1 рабочий.Нюанс:
   `mdls` ещё показывал старый тип (кеш Spotlight) — истину даёт `URLResourceValues`/
   `UTType`, не `mdls`.
3. **Невод `public.data` ловит ровно безрасширенные** (лист `public.data`):
   Dockerfile, .gitignore, LICENSE-без-расширения и т. п. Внутри `resolvePreview`
   имя файла → язык (docker) или нейтраль. Бинарь без расширения тоже приходит,
   но не-UTF-8 бросает → системный дженерик, мусор не показываем. Жадность
   управляемая.
4. **Неизвестные расширения (`.xyz`) невод НЕ ловит** — их лист `dyn.*`, а не
   `public.data`; перехват идёт по точному листу. Поймать конкретное неизвестное
   расширение можно только явным своим UTI на него (механизм 1).

**Косметика на заметку:** нейтральный показ `.gitignore` вышел чёрным-по-белому
при системной тёмной теме — страница нейтрали (`neutralPageHTML`, Canvas/CanvasText)
похоже не подхватывает тёмный режим QL-вебвью. Не блокер, кандидат на правку.

**Документальное подтверждение (первоисточники, не только эмпирика и чужой код):**
- **Классы тегов UTI — только два.** Apple `UniformTypeIdentifiers`: у `UTTagClass`
  всего две константы — `filenameExtension` (`public.filename-extension`) и
  `mimeType` (`public.mime-type`); «Uniform Type Identifiers don't store tag
  information for nonstandard tag classes». → **тега на целое имя файла нет
  официально**, безрасширенные конфиги своим UTI не поймать. (Совпало: доки Apple
  + Info.plist sbarex 170 тегов только extension/mime + спайк.)
- **Приоритет — документирован только один.** «If both exported and imported
  declarations for a type exist, the exported declaration takes precedence over the
  imported declaration». Про конфликт «два приложения ЭКСПОРТируют один тип / claim
  одно расширение» — в документации **ничего**. → межпрограммный конфликт Apple
  официально НЕ определяет; исход опаковый, зависит от машины (наш `.nim` проиграл).
- **Обсуждение на форуме Apple (thread 747506, `.3mf`-конфликт):** ответа инженера
  Apple нет; приём сообщества — перечислить в своём бандле сразу несколько UTI
  (свой + конкурентов) и дать пользователю выбрать. Для нас **не подходит**:
  закладываться на конкретного конкурента (sbarex) нельзя — на других машинах его
  нет. Фиксируем как известный, но отвергнутый вариант.
- **Тип и QL-расширение — разные подсистемы.** `UTExportedTypeDeclarations` живут в
  базе LaunchServices (регистрируются при установке приложения), а включённость
  QL-расширения — отдельно (pluginkit). Поэтому экспорт sbarex держит лист `.nim`
  даже с ВЫКЛЮЧЕННЫМ его превью-расширением.

**Что это даёт продукту (для решения по объёму):**
- Механизм 1 (свои UTI) — берёт **свободные** расширения (`.ts`, `.kt`, `.graphql`,
  `.dart`, `.nim` без sbarex…); занятые конкурентом — спорные, не гарантированы.
- Механизм 2 (невод `public.data`) — берёт **безрасширенные** конфиги; бинарь
  отсеивается сам; неизвестные расширения не покрывает.
- Спайк-ветка `spike/uti-tail` — выбросить после решения (правки только в
  `project.yml`, кода не трогали).
